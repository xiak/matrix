# 策略结构、权限分类与资源标识

## 策略内容

策略以文档表达授权语义，不以名称或表格标签决定权限。CAM 文档包含语法版本和多条语句；语句使用 effect、action、resource、condition 等元素。principal 在信任策略、资源策略等适用上下文中表达主体，不能把一种策略的 principal 规则套用到所有策略。[^1][^2]

| 元素 | 回答的问题 | 适合呈现的内容 |
| --- | --- | --- |
| effect | 允许还是拒绝？ | 明确文字，不只用颜色 |
| action | 允许执行什么？ | 服务、具体操作、操作类别 |
| resource | 针对哪些资源？ | 全部、具体标识或匹配规则 |
| condition | 什么情况下生效？ | 键、运算符、值及组合关系 |
| principal | 授权或信任谁？ | 仅出现在适用的策略类型 |

一条策略可含多个服务的操作。“关联产品”“策略名称”“描述”只是帮助检索和理解的元数据，不能替代正文的实际范围。预设策略由腾讯维护，自定义策略由账户管理者定义；修改预设策略备注不等于能修改其授权文档。预设策略还可能随云产品能力更新。[^3][^4]

## 策略 TABLE 的权限级别

已观察的腾讯策略列表使用“全局权限、财务权限、云产品权限”。这是页面上的策略范围分类，不是读取／写入等级，也不是 RBAC／ABAC 分类。该结论是策略目录页面观察，不推定公开 API 有同名枚举。[^5]

| 维度 | 示例 | 决定什么 |
| --- | --- | --- |
| 策略范围分类 | 全局、财务、云产品 | 列表检索和风险理解 |
| 操作类别 | 读、写、列表、其他 | 编辑器中如何寻找操作 |
| 授权粒度 | 服务级、操作级、资源级 | 能否限制到某个 API 或资源 |

授权粒度依服务和操作能力而定，不是每个服务的每个操作都支持相同粒度。此前生成器中，CVM 的 RebootInstances 支持指定实例，AllocateAddresses 显示为操作级；这些是已观察到的例子，不是全产品能力清单。泛化规则应以官方支持目录和具体产品接口为准。[^6][^7]

ReadOnlyAccess 也不是“所有页面均可打开”。腾讯说明其面向操作级、资源级产品的读接口；服务级产品或写接口可能仍然无权限。不要根据 Get/List/Describe 命名前缀自行生成一个声称完整安全的只读策略。[^4]

## 资源六段式

腾讯资源描述的基本形态为：

    qcs:project_id:service:region:account:resource

它包含服务、地域、资源所属账户和产品定义的资源类型／ID 或路径。project_id 是历史保留位，当前自定义策略语法要求置空；不能因此把“项目”重新当成全平台的一级授权边界。账户字段的 UIN 与特定产品使用的 UID／APPID 也不能混用。[^8]

以下仅为虚构的说明性标识，不对应真实资源或已经验证的提交方案：

    qcs::cvm:ap-shanghai:uin/111111111111:instance/ins-example

策略可以匹配明确资源，也可以使用产品允许的通配规则。因此，授权关系不一定是一张逐个枚举用户和资源的关联表。资源库存变化与策略规则变化可以独立发生。

六段式中空字段的含义并不完全一致：空地域表示所有地域，空账户则使用创建策略的 CAM 用户所属主账号，不能都解释为任意值。资源所有者是主账号；子用户创建资源不等于自动获得访问权。[^8]

### COS 例子：资源模板由产品和操作决定

COS 接口表将每个操作的授权粒度、资源六段式和 IP 支持并列。例如对象路径使用桶名与 APPID 组成的桶标识，再接对象路径；向量接口则使用 cosvector 服务前缀以及 bucket／index 层级。不能把所有产品的最后一段都当成统一的 instance/ID，也不能将 uid/APPID 当作子用户 UIN。[^11]

这张表不是完整的资源命名通则：同一个 GetObject 出现多条不同占位符写法，另有部分操作列出多个服务的资源模板。应结合具体产品授权指引核实操作、标识和依赖，不能直接抓取目录表生成无校验的生产契约。资源选择器中的展示名称、稳定资源标识和通配规则应分开。[^8][^11]

## 不支持资源级的操作

生成器应依操作能力决定是否显示资源选择。部分服务／操作只能用“*”资源，这意味着资源范围较宽，不能继续描述为仅授权某个实例；它不代表所有其他条件都自动失效。[^6][^7]

创建资源时，目标资源可能尚未有 ID，所需的请求条件与现存资源条件也不同。标签相关语义见 [评估与 ABAC](evaluation-and-abac.md)，不可仅凭 UI 有资源选择框就假设后台能按任意粒度鉴权。

支持目录提供产品简称、最细授权粒度、控制台和标签支持入口，但仍需读每个操作的资源与条件能力。批量计算的 CreateComputeEnv、DescribeComputeEnvs 支持资源级，ModifyComputeNodeAttribute 却是操作级；CreateComputeEnv 与 CreateCpmComputeEnv 的 IP 支持也不同。因此 Create/List/Describe 命名或“读／写／列表”分类都不能决定授权粒度或条件支持。[^9][^10]

## 三种版本

策略 JSON 的 version 表示语言版本；策略保存的 VersionId 表示内容修订；API 的 Version 表示接口契约版本。这三者必须分离。策略修订与默认版本行为见 [API 契约](../api/contracts.md)；官方语言版本文档的不一致见 [证据限制](../evidence/caveats.md)。
