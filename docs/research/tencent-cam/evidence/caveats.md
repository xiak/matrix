# 证据限制、例外与版本差异

## 如何使用

本页拥有“结论在哪些条件下不能直接使用”的说明。主题的正常语义仍在各自概念、API 或 UX 文档中。来源元数据与实际阅读范围见 [阅读覆盖](reading-map.md)；文档更新时间不是 Matrix 的运行验证时间。

## 需要保留的差异

| 主题 | 容易过度概括的结论 | 证据与适用边界 |
| --- | --- | --- |
| Deny | 任何服务、任何接口都能用显式拒绝覆盖允许 | 一般评估指南说明拒绝优先；专门限制指南同时列出部分列表、匿名 COS 和财务授权场景的例外。不能省略后一层限制。[^1][^2] |
| 权限边界 | 权限边界可限制所有返回的数据 | 文档明确写有资源列表类接口暂不覆盖的限制。它不能代替产品侧列表隔离验证。[^3] |
| 编辑策略 | 修改内容总是创建新版本 | 控制台指南描述新建修订；公开 UpdatePolicy 修改现有默认版本。不同管理命令的契约不同，并不证明控制台内部调用了哪个接口。[^4][^5] |
| 策略语言 | 腾讯策略版本 3.0 可以普遍使用 | 较新的语法结构页只明确给出 2.0；较旧分析器页提及 2.0／3.0。未确认通用 3.0 契约，不能据此启用导入。[^6][^7] |
| 条件能力 | 通用文档列出的四个条件键就是全部可用键 | 角色 ABAC 与重要预设策略文档出现其他专用键。通用键、产品支持和内部预设能力不能混成一个无约束选项表。[^8][^9][^10] |
| 标签向导 | 任意标签组合都支持相同的列表行为 | 标签指南区分任意与组合匹配，并注明组合匹配的列表限制；部分说明文案有 request_tag／resource_tag 混用。应核对 JSON、运算符和目标动作，不按文案猜测。[^11][^12] |
| 用户／角色 SSO | 角色 SSO 与用户 SSO 都只是在找同一种 CAM 用户 | SSO 概览的部分简介措辞含混，但分项比较和 API 明确区分映射用户与获取角色会话。采用分项契约，不把简介当成单一身份模型。[^13][^14] |
| SSO 协议 | 角色 OIDC 天生无法用于任何控制台 | 文档“不支持控制台登录”是腾讯该功能的能力说明，不是 OIDC 协议的一般限制。[^13] |
| 搜索与分页 | 控制台的筛选一定就是公开 ListPolicies 的参数 | 本研究只确认公开接口及界面表现，没有控制台私有实现证据。公开 Keyword 描述为策略名搜索。[^15] |
| 版本关联 | 所有策略关联都固定某个历史版本 | 重要预设策略页有特定策略的历史版本说明；自定义策略指南描述关联主体跟随默认版本。不能用一项迁移公告推导全部关联模型。[^4][^10] |
| 删除策略 | 删除一定自动解绑，或者一定要求先全部解绑 | DeletePolicy 的公开说明未覆盖所有关联清理与批量原子性场景。两种全局结论都缺少充分证据。[^16] |
| 网络策略 | 密钥级网络限制与账户级规则总是取交集 | 该功能规定密钥级规则替代账户级规则；还有限定开放范围、凭证类型、产品与传播时间。不能沿用权限边界的组合公式。[^17] |

## 不能从目录补出的契约

CAM API 分类只是公开管理接口组织方式，不足以证明腾讯内部微服务、数据库表、事务边界或权限计算引擎。控制台某个向导包含多个步骤，也不说明跨对象写入具有原子性。

本集合核对的是 CAM 当前 API 概览及选定的 `2019-01-16` 接口文档。搜索结果中仍可能出现旧版本接口；不能把旧接口名、参数、签名方式和新版本契约拼接使用。公共参数中的接口版本、策略 JSON 语言版本、某条策略的修订编号，属于不同概念。[^6][^18][^19]

STS 普通 AssumeRole、SAML 断言交换、OIDC 令牌交换应分别核查认证参数。已读接口文档不足以给出会话策略、所有资源策略、组织控制策略和权限边界的完整组合公式，也没有覆盖令牌撤销与各处缓存的真实传播测试。[^14][^20][^21]

## 阅读与验证不是一回事

本集合是官方来源研究与已有界面观察，不是腾讯运行环境的安全测试报告。界面路径观察以未提交表单为界；真实授权、密钥发行、提供商启用、收费路径和需要扫码确认的流程未执行，不将其标成验证成功。

没有逐项验证全部云产品的每个 Action、资源类型和条件键，也没有逐篇精读 API 目录中的全部接口。企业组织治理、SCP 的完整组合规则、全部 SDK 和签名实现、所有认证失败及恢复流程，都不在本次已证明范围内。各条阅读状态以 [覆盖记录](reading-map.md) 为准。

Matrix 的真实实现与安全验收只能由所属 FEAT 的测试和运行证据说明。这里的腾讯例外不应变成 Matrix 的兼容承诺；这里的 Matrix 建议也不自动扩大现有后端接收的策略能力。
