# 策略版本与策略分析

## 不可变版本

一个托管策略可以拥有多个不可变版本，其中一个是默认生效版本。编辑策略会创建新版本；切换默认版本完成发布或回滚。版本包含内容摘要、创建者、创建时间、变更说明和分析结果。

策略支持多个不可变版本、默认版本切换和历史版本回滚。[^1]

## 生命周期

1. 创建策略草稿。
2. 执行 schema 校验与产品词汇解析。
3. 运行静态分析和权限差异比较。
4. 发布为不可变版本。
5. 选择默认版本并记录生效修订。
6. 观察拒绝、允许和业务错误。
7. 必要时切换回历史版本。
8. 删除非默认且不再被审计解释依赖的版本内容；保留摘要。

版本数量受配额限制。达到上限时，系统要求显式选择可删除的非默认版本，不能自动覆盖最旧版本。

## 策略分析器

策略分析器与运行时使用同一 schema、动作目录、资源解析和条件操作符。分析结果分为错误和警告：错误阻止发布，警告要求具备权限的操作者确认。

### 结构错误

- 缺少版本或 statements。
- 未知字段、重复字段、空数组和非法 effect。
- principal 出现在不支持的策略类型。
- 超出文档大小、statement 或嵌套限制。

### 语义错误

- 未注册产品、动作、资源类型或条件键。
- 动作与资源类型不匹配。
- 条件值类型与操作符不匹配。
- 永远不可能匹配或互相矛盾的条件。
- 产品只支持服务级授权却声明具体资源。

### 风险警告

- 对所有资源允许敏感写动作。
- 可修改自身策略、权限边界、角色信任或访问密钥。
- `PassRole` 未限制目标服务或角色。
- 允许修改用于 ABAC 的授权标签。
- 跨账号信任缺少外部 ID、受众或主体约束。
- 明确拒绝范围可能导致管理恢复路径丢失。

策略分析器系统校验版本、statement、effect、principal、action、resource、condition 与未知元素。[^2]

## 权限差异

发布前比较旧默认版本与新版本的新增允许、新增拒绝、移除允许和条件变化。通配符先按当前产品能力修订展开；结果固定到该修订，避免产品未来新增动作时静默扩大旧策略。

## 策略模拟

模拟 API 接受主体、动作、资源与上下文，固定策略和产品能力修订，返回解释树但不执行业务动作。模拟本身受授权并写审计，不能用来枚举其他账号的策略或资源。
