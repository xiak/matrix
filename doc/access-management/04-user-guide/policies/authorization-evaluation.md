# 授权评估引擎

授权评估把主体、动作、资源、上下文和所有适用策略归并为一个确定的允许或拒绝结果。核心逻辑是默认拒绝、收集相关策略、明确拒绝优先、存在允许时才允许。[^1]

## 输入

```yaml
subject:
  account_id: account-a
  principal_id: user-123
  session_id: session-456
  original_principal_id: user-123
action: compute.instance.stop
resources:
  - crn:compute:region-a:account-a:instance/i-001
context:
  request.source_ip: 203.0.113.10
  request.time: 2026-09-10T10:00:00Z
  principal.tag.department: engineering
  resource.tag.environment: production
```

主体与网络上下文来自认证和网关，动作与资源来自业务产品，资源属性来自产品的可信解析器。客户端不能直接声明已认证主体或最终资源范围。

## 求值步骤

1. 验证产品、动作、资源类型和上下文 schema。
2. 收集用户直接策略、用户组策略和当前角色策略。
3. 收集适用资源策略、会话策略、权限边界和组织护栏。
4. 展开动作与资源匹配，计算条件。
5. 任一适用 statement 为明确拒绝时返回拒绝。
6. 没有适用允许时按默认拒绝返回。
7. 将候选允许与会话策略、权限边界、组织护栏分别取交集。
8. 在跨账号场景中同时验证身份侧与资源侧授权。
9. 输出结果、理由码、命中 statement、策略版本和产品能力修订。

## 多策略语义

身份策略之间的允许通常取并集；明确拒绝跨策略生效。权限边界、会话策略和组织护栏是上限，与候选允许取交集。资源策略是否可以单独授权取决于主体类型和跨账号规则，必须在产品协议中固定，不能由界面猜测。

## 多资源请求

一个请求包含多个资源时，默认要求每个资源都允许。批量 API 可以返回逐资源决定，或声明事务原子且任一拒绝导致整批拒绝。不能只检查第一个资源。

## 列表请求

列表接口有三种安全模型：

- 整体动作授权：允许后可列出该范围内全部资源。
- 服务端资源过滤：根据每个资源的策略和属性只返回允许项。
- 只返回不可识别摘要：用于无法高效逐项求值但又需避免枚举的场景。

产品授权能力声明必须选择一种模型。仅在 UI 隐藏无权资源不能构成授权。

## 明确拒绝

明确拒绝适合组织禁区、敏感动作和紧急封锁。拒绝 statement 同样必须匹配动作、资源和条件。诊断工具需要显示未命中的原因；“存在一个 deny”并不意味着它对所有请求生效。

## 决定输出

决定包含唯一 ID、结果、公开理由码、主体与原始主体、动作、资源摘要、认证强度、命中策略版本、边界/护栏修订、产品能力修订和求值时间。敏感策略内容只在有诊断权限时展示。
