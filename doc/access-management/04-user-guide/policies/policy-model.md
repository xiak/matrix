# 策略模型

策略以结构化文档描述主体或资源的访问规则。策略由不可变版本和 statement 集合组成，可作为预置托管策略、自定义托管策略、内联策略、资源策略、信任策略或权限边界使用。

## 策略类型

| 类型 | 绑定位置 | 用途 |
| --- | --- | --- |
| 身份策略 | 用户、组、角色 | 定义主体可对哪些资源执行哪些动作 |
| 资源策略 | 业务资源 | 定义哪些主体可访问该资源 |
| 信任策略 | 角色 | 定义哪些主体可承担角色 |
| 会话策略 | 临时角色会话 | 在一次会话内进一步收窄权限 |
| 权限边界 | 用户、角色 | 定义该主体可获得的最大权限 |
| 组织护栏 | 账号或组织单元 | 限制成员账号可获得的最大权限 |

## 文档结构

```json
{
  "version": "iam-policy/v1",
  "statements": [
    {
      "sid": "ReadProjectResources",
      "effect": "allow",
      "actions": ["storage.object.read"],
      "resources": ["crn:storage:region:account:bucket/example/*"],
      "conditions": {
        "ip_in": {
          "request.source_ip": ["203.0.113.0/24"]
        }
      }
    }
  ]
}
```

策略文档由 version 与 statement 组成；statement 使用 effect、action、resource、condition，并在信任或资源策略中使用 principal。[^1]

## 元素

### Version

标识策略语言版本，而不是策略修订号。语言版本固定字段与操作符语义；策略修订由 PolicyVersion 独立管理。

### Statement ID

可选稳定标签，用于解释、审计和变更比较，不参与授权逻辑。

### Effect

只能是 `allow` 或 `deny`。未知值和大小写变体在发布时拒绝。

### Action

动作采用 `product.operation` 或等价的稳定命名空间。动作必须由产品授权能力注册表声明。通配符只在明确允许的层级使用，策略分析器展示实际展开集合。

### Resource

资源使用规范资源名或类型化引用，包含产品、地域、账号、资源类型与资源路径。全局资源显式省略或使用专用全局标记，不能用空字符串猜测。

### Principal

只在资源策略和信任策略中出现，可引用账号、用户、角色、服务或身份提供商。主体 ID 与显示名分离。

### Condition

条件把可信请求、主体、会话、资源或环境属性与值比较。每个键和操作符有类型，禁止隐式字符串转换。

## 托管策略

预置策略由平台维护并随产品动作演进；变更应发布修订说明和影响分析。自定义托管策略由账号维护，可以绑定多个实体并有独立版本。内联策略随单一实体生命周期存在，适合不可复用的局部规则。

## 规范化与编译

管理 API 接受 JSON 或等价结构后，先执行 schema 校验、产品词汇解析、资源规范化和静态分析，再生成规范 AST。运行时 PDP 只求值已编译版本，不解释任意脚本或自由文本。
