# 权限边界与委派管理

权限边界是绑定到用户或角色的最大权限策略。它不授予任何权限，只限制身份策略、组策略或角色策略产生的候选允许。[^1]

## 求值关系

```text
用户有效允许 =（用户策略 ∪ 组策略）∩ 用户权限边界

角色有效允许 = 角色策略 ∩ 会话策略 ∩ 角色权限边界

最终允许 = 上述结果 ∩ 组织护栏 − 任意明确拒绝
```

只有边界允许而身份策略没有允许时，结果仍然拒绝。边界中的明确拒绝和其他适用策略的明确拒绝都优先。

## 使用场景

### 委派身份管理员

中央安全团队允许部门管理员创建用户、组、角色和策略，但为其创建的主体强制绑定部门边界。部门管理员可以在边界内组合权限，不能授予跨部门或高风险安全管理动作。

### 限制工作负载角色

平台允许团队管理应用角色，但边界排除身份管理、费用管理和其他环境资源。即使角色策略误设为通配符，实际权限仍被边界收窄。

### 限制外部协作者

外部协作者的用户或角色统一绑定合作范围边界；直接策略、组策略和会话策略均不能突破该范围。

## 管理规则

- 创建、更新、绑定、解绑和删除权限边界分别需要受保护动作。
- 边界引用不可变策略版本，授权决定记录实际版本。
- 委派管理员不能移除约束自身管理能力的边界。
- 创建用户或角色的授权可要求必须附带指定边界。
- 删除边界前检查所有用户、角色和模板绑定。
- 放宽边界前生成有效权限差异并要求 step-up 或审批。

## 防止提权

仅限制业务 API 权限不足以实现安全委派。还必须限制管理员可以：

- 创建或修改哪些策略；
- 把策略绑定给哪些主体；
- 修改哪些角色信任关系；
- 传递哪些角色给哪些服务；
- 修改哪些主体或资源授权标签；
- 修改或移除哪些权限边界。

这些管理动作进入同一个产品授权目录并接受边界求值。

## 诊断

无权限解释应分别显示身份策略是否允许、边界是否包含、组织护栏是否允许以及是否存在明确拒绝。只显示“策略未授权”会掩盖边界交集，是常见运维误区。
