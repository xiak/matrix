# 授权故障诊断

授权故障诊断从实际请求证据开始，而不是先创建更宽策略。每次拒绝应返回请求 ID、决定 ID、产品、动作、资源摘要和公开理由码，使管理员可以重放同一求值上下文。

## 诊断顺序

1. **确认认证身份**：账号、用户、角色会话和原始主体是否符合预期。
2. **确认产品动作**：实际 API 映射到哪个动作，是否包含隐式的辅助动作。
3. **确认资源**：资源所属账号、地域、类型、父子层级和规范资源名是否正确。
4. **确认候选允许**：用户、组或角色策略中是否存在匹配允许。
5. **查找明确拒绝**：身份策略、资源策略和组织护栏中是否有匹配 deny。
6. **检查权限上限**：会话策略、权限边界和组织护栏是否包含该动作与资源。
7. **检查条件**：来源 IP、时间、MFA、标签、外部 ID 或受众是否满足。
8. **检查传播**：决定使用的策略和产品能力修订是否已包含最近变更。
9. **检查业务错误**：授权允许后，产品仍可能因资源状态或业务规则拒绝。

## 常见理由码

| 理由码 | 含义 | 处理方向 |
| --- | --- | --- |
| `NO_MATCHING_ALLOW` | 没有适用允许 | 补充最小动作、资源和条件 |
| `EXPLICIT_DENY` | 命中明确拒绝 | 找到具体 deny 与条件，不叠加 allow |
| `BOUNDARY_EXCLUDES` | 权限边界未包含 | 审查委派范围，而非仅修改身份策略 |
| `GUARDRAIL_EXCLUDES` | 组织护栏限制 | 由组织治理管理员处理 |
| `CONDITION_MISMATCH` | 条件不成立 | 比较可信上下文与策略期望 |
| `UNKNOWN_ACTION` | 产品动作未注册 | 检查产品能力版本与 API 映射 |
| `RESOURCE_MISMATCH` | 资源类型或名称不匹配 | 使用产品返回的规范资源引用 |
| `TRUST_DENIED` | 角色信任不允许承担者 | 同时检查调用者承担权限和角色信任 |
| `STALE_REVISION` | 执行点尚未获得要求的修订 | 等待传播或刷新安全缓存 |

诊断工具可以根据无权限信息生成候选策略，并解释 deny 看似未生效的条件与策略组合场景。[^1][^2]

## 安全约束

- 普通调用者只看到自身请求的必要信息。
- 管理员解释接口按账号和策略读取权限脱敏。
- 诊断工具不自动发布策略，只生成候选差异。
- 模拟固定策略和产品能力修订，避免结果在分析中变化。
- 诊断、导出和查看敏感策略均写审计。
