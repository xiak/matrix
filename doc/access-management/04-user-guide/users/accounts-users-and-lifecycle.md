# 账号、用户与用户生命周期

## 账号与根身份

账号是资源所有权和访问管理的顶层边界。根身份在账号创建时产生，拥有所有权确认、安全恢复和少量不可委派能力。根身份不是普通用户，不加入组、不承担日常业务角色，也不用于应用访问密钥。

根身份应启用强 MFA、独立恢复渠道和使用告警。日常管理由可撤销的管理员用户或角色完成。

## 用户类型

| 类型 | 身份来源 | 是否可认证 | 典型用途 |
| --- | --- | ---: | --- |
| 本地用户 | 账号内创建 | 是 | 管理员、开发者、审计人员 |
| 企业目录用户 | 外部目录导入或映射 | 是 | 统一员工生命周期与 SSO |
| 外部协作者 | 另一个账号或外部身份 | 是 | 跨组织合作与临时支持 |
| 服务用户 | 自动化创建 | 是 | 无工作负载身份能力的旧系统 |
| 通知联系人 | 联系方式或订阅系统 | 否 | 接收安全、费用或运维通知 |

可授权用户、企业目录用户、外部协作者与只接收消息的联系人属于不同对象类型。[^1]

## 用户模型

用户包含稳定 ID、所属账号、登录标识、显示信息、身份来源、状态、认证方式、属性、标签与时间戳。用户名和邮箱可以变化，不作为业务资源外键；稳定用户 ID 删除后不得复用。

### 状态

- `PENDING`：已创建但未完成激活。
- `ACTIVE`：允许认证并参与授权。
- `SUSPENDED`：临时阻止认证和新会话，保留绑定与审计关联。
- `DEPROVISIONED`：离职或永久关闭，凭据与会话已撤销。
- `DELETED`：完成引用检查后的终态，历史审计仍保留不可逆标识。

状态变化必须原子影响新认证。对现有会话的处理由安全策略决定：普通暂停可有短传播窗口，确认泄露时立即全局撤销。

## 生命周期

### 创建与激活

创建用户时选择身份来源、访问方式和初始安全策略。交互式用户通过一次性激活完成密码设置或 IdP 绑定；系统不发送可长期复用的明文密码。

### 授权

权限通过用户组、直接策略、角色承担或属性策略获得。直接绑定适合例外，不应成为大规模人员管理的默认方式。

### 修改

显示信息与联系方式变化不改变用户 ID。登录标识、身份来源、安全因子和授权属性变化属于高风险管理事件，需要独立权限与审计。

### 禁用与离职

离职流程依次阻止新认证、撤销会话和访问密钥、终止角色承担、解除授权关系，并在保留审计引用后删除。删除不能让旧用户名或 ID 的审计记录指向新用户。

## 账号摘要

账号摘要展示用户、组、角色、策略、身份提供商和访问密钥的数量与配额，标记无 MFA 管理员、长期未登录用户、活跃根密钥和高风险策略，作为治理入口。
