# 登录保护与操作保护

身份认证安全由密码规则、登录来源、风险检测、MFA、会话管理和敏感操作 step-up 共同组成。任一单项控制都不能替代其他层。

## 密码策略

- 最小长度与复杂度要求。
- 拒绝常见密码、用户名变体和已泄露密码。
- 密码历史与最短变更间隔，防止循环复用。
- 登录失败速率限制、渐进延迟和有界锁定。
- 安全恢复使用一次性、短期、受审计令牌。
- 密码以专用口令哈希保存，不可解密查询。

密码长度、复杂度、有效期、历史和失败锁定由账号级安全策略统一管理。[^1]

## MFA

MFA 因子可以是 TOTP、安全密钥/WebAuthn、受控自定义因子或其他抗钓鱼机制。产品按主体风险和动作风险要求认证强度：

- 管理员登录必须 MFA。
- 创建或删除访问密钥、修改 IdP、放宽权限边界等操作必须 step-up。
- 角色信任策略可要求承担者已完成 MFA。
- 根身份和恢复流程使用独立的强因子。

因子注册、替换、恢复和删除都必须验证当前主体，并生成高风险审计事件。恢复码只显示一次、加密保存且使用后失效。

## 登录限制

账号或用户可以配置来源 IP/CIDR、VPC、地域、时间窗和允许的登录方式。来源网络由可信代理链构造，不接受客户端伪造头。异常登录检测可以触发额外验证、阻止登录或告警，但规则结果要有理由码，避免不可诊断的黑箱拒绝。

IP 限制、异常检测和二次验证共同构成登录限制，并支持有期限、有审计的临时例外。[^2]

## 操作保护

敏感操作保护在已有会话内重新验证用户，生成短期 step-up 证据。操作策略可按动作风险要求密码重验、MFA、安全密钥或多人批准。step-up 证据绑定主体、会话、动作范围和过期时间，不能在另一会话复用。

## 会话管理

- 绝对有效期限制单次登录最长寿命。
- 空闲有效期在无活动后结束会话。
- 密码或 MFA 重置、用户禁用和风险事件支持全局撤销。
- 会话列表显示客户端、创建时间、最近活动、认证强度和来源摘要。
- 浏览器会话使用安全 Cookie；API 会话使用有受众和作用域的短期令牌。

## 闲置用户

系统依据最后登录、最后 API 调用、活跃密钥和角色承担记录识别闲置用户。闲置策略可提醒、限制新会话或暂停用户；自动处置前显示数据水位和例外，避免因审计延迟误判。
