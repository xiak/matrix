# 服务角色与资源角色

业务产品经常需要代表账号访问另一个产品，例如编排服务创建网络资源、计算任务读取对象存储、流水线发布应用。服务角色把这种代表关系建模为可审计的临时委派。

## 角色类型

### 服务角色

管理员创建或选择角色，并把角色传递给业务产品。角色信任策略允许指定服务主体承担，权限策略由管理员控制。适合客户可选择权限范围的集成。

### 服务关联角色

角色与某个产品能力的生命周期绑定。产品声明固定信任主体和受控权限模板，在启用功能时创建，在所有依赖资源解除后删除。适合产品正常运行必需且结构稳定的跨服务权限。

### 资源角色

角色与具体资源实例绑定，例如某个计算实例、容器工作负载或函数。运行时通过不可伪造的资源证明取得短期会话，资源删除时解除绑定。

角色模型包含服务角色、服务关联角色和基于资源的服务角色，用于让云服务或资源代表账号访问其他服务。[^1]

## PassRole

把角色交给服务是独立授权动作。一次 PassRole 校验至少包含：

- 传递者是否有权传递该角色；
- 目标服务是否在角色信任策略中；
- 角色是否允许用于目标业务动作；
- 任务资源和角色是否属于允许的账号或范围；
- 组织护栏与权限边界是否允许。

仅拥有创建业务任务的权限不自动意味着可以传递任意高权限角色。

## 产品接入契约

支持服务角色的业务产品发布：角色用途、可信服务主体、所需动作、资源范围、创建/更新/删除时机、是否支持自定义角色、会话时长和审计事件。产品升级若需要新增权限，先发布影响说明并取得管理员授权。

## 工作负载凭据

资源内的应用通过本地元数据端点或工作负载身份 API 获取短期凭据。端点必须绑定资源身份，防止其他租户、容器或网络命名空间读取；返回的凭据具有较短有效期并自动刷新。

## 删除保护

服务关联角色存在活跃产品资源时拒绝删除，并返回阻塞资源列表。产品资源全部解除后，删除任务可异步执行并提供状态。角色删除不删除业务资源，也不抹除历史审计。
