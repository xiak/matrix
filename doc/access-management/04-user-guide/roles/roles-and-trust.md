# 角色与信任关系

角色是可被可信主体临时承担的虚拟身份。角色没有登录密码和永久访问密钥；承担成功后由安全令牌服务发行有时限的角色会话。

## 角色组成

| 组成 | 回答的问题 | 主要内容 |
| --- | --- | --- |
| 信任策略 | 谁可以承担角色 | 账号、用户、服务、资源、IdP、条件 |
| 权限策略 | 角色可以做什么 | 动作、资源、条件、明确允许/拒绝 |
| 权限边界 | 角色最多可以做什么 | 最大权限策略 |
| 会话设置 | 一次承担如何受限 | 最大时长、控制台登录、MFA、会话标签 |

角色的信任策略与权限策略相互独立：前者定义承担者，后者定义角色能力。[^1]

## 可信主体

- 本账号中的用户或服务身份。
- 另一个账号或其指定主体。
- 已注册的云服务。
- 与业务资源绑定的运行时身份。
- SAML 或 OIDC 身份提供商。
- 组织身份中心发行的主体。

信任策略使用稳定主体 ID 和条件，不能仅依赖可变显示名。跨账号或第三方服务承担应使用受众、外部 ID、来源账号、MFA 或资源绑定，防止混淆代理攻击。

## 角色生命周期

### 创建

创建角色时先选择可信主体类型，再配置最小信任条件、最大会话时长和权限策略。创建者不能借助自己可编辑的信任策略绕过承担权限。

### 修改

信任策略、权限绑定、会话时长和描述独立更新。每次变更产生不可变版本或修订，授权决定记录实际版本。

### 使用

调用者必须同时满足自身的承担角色权限和目标角色的信任策略。承担结果是 RoleSession，不改变原主体的长期身份。

### 删除

删除前检查产品生命周期引用、资源绑定和活动会话。角色 ID 不复用；删除策略明确现有会话是立即撤销还是在短窗口内到期。

## 角色链

允许角色会话继续承担另一个角色时，产品必须限制链深度和会话时长，并始终保留最初主体。每一跳都重新校验承担权限、目标信任和组织护栏，不能只信任上一跳角色名称。

## 控制台角色会话

角色可配置是否允许控制台会话。控制台登录链接或令牌是一次性、短期且绑定目标角色；不得把 STS Secret 放入 URL。界面始终显示当前角色、所属账号、原始身份和会话剩余时间。
