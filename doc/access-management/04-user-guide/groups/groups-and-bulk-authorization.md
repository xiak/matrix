# 用户组与批量授权

用户组把具有相同职责的人员组织在一起，并承载统一策略绑定。用户通过成员关系继承组策略，减少逐用户复制和离职遗漏。

## 模型

Group 包含账号、稳定 ID、名称、描述和状态。Membership 连接用户与组，并记录添加者、时间和来源。组本身不能认证、不能承担角色，也不拥有业务资源。

策略可以同时绑定多个组，一个用户也可以属于多个组。有效身份策略是用户直接策略与所有组策略的并集，再接受明确拒绝、会话策略、权限边界和组织护栏处理。

## 操作

- 创建、修改和删除用户组。
- 批量添加或移除用户。
- 绑定或解除托管策略。
- 查询组成员和用户所属组。
- 查询组的有效策略与最近变更。
- 在删除前检查成员和策略引用。

用户组管理拆分为创建、成员添加/移除、策略绑定/解除和删除；成员关系与策略关系具有独立生命周期。[^1]

## 设计规则

- 用户加入组立即获得组的候选允许，也立即受到组内明确拒绝。
- 从组移除后，安全收紧应优先传播到授权执行点。
- 组名可变，策略与审计使用稳定 Group ID。
- 组成员 API 支持幂等添加与幂等移除。
- 批量变更明确采用全有或逐项结果，不能只返回模糊成功。
- 若支持嵌套组，必须检测循环、限制深度并在有效权限中展示继承路径。

## 职责组示例

- 账号安全管理员：管理认证策略、密钥和 IdP。
- 访问管理员：管理用户、组、角色和策略，但受权限边界约束。
- 业务开发者：操作指定产品与项目资源。
- 审计读取者：查看认证、授权决定和操作记录，不修改权限。
- 费用查看者：访问费用与账单，不获得业务资源写权限。

组表达稳定职责；临时任务、高权限操作和跨账号访问使用角色会话更合适。
