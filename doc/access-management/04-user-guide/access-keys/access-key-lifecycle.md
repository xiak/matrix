# 访问密钥生命周期

访问密钥用于非交互式 API 签名，由可公开标识的 Key ID 和必须保密的 Secret 组成。永久密钥适合无法使用工作负载身份或短期令牌的兼容场景；自动化优先使用角色会话和 STS。

## 创建

创建访问密钥前验证主体状态、创建权限、MFA/step-up 和配额。Secret 只返回一次，之后管理 API 仅显示 Key ID、状态、创建时间和使用元数据。系统保存不可逆验证材料或受密钥管理系统保护的秘密，不允许管理员再次读取明文。

Secret 只在创建时获取；密钥生命周期包含启用、禁用、撤销、删除和使用记录。[^1]

## 状态

- `ACTIVE`：可以用于签名验证。
- `INACTIVE`：暂时不接受，可重新启用。
- `REVOKED`：永久撤销，不能恢复。
- `DELETED`：从活动管理视图移除，历史审计引用保留。

禁用和撤销属于安全收紧操作，拥有优先传播和缓存失效通道。

## 轮换

1. 创建第二把密钥。
2. 将新密钥部署到调用方。
3. 通过最近使用记录确认新密钥已工作。
4. 禁用旧密钥并观察失败。
5. 在回退窗口结束后撤销和删除旧密钥。

系统应允许短时间并存至少两把密钥，以支持无中断轮换；同时通过配额阻止长期堆积。

## 最近使用

密钥详情聚合最后使用时间、产品、动作、地域和来源网络摘要。数据可能来自异步审计投影，因此界面显示数据水位。没有观察到使用不能单独证明密钥可安全删除，应结合所有调用环境确认。

## 网络访问限制

密钥可绑定来源公网 IP、CIDR、VPC 或网络区域。网络策略在签名验证后、业务授权前执行，失败返回专用理由码。账号级规则提供默认范围，密钥级规则用于更窄限制；组合语义必须明确是交集而不是覆盖。

永久访问密钥支持账号级与密钥级网络限制；临时 STS 凭据使用独立的会话与信任控制。[^2]

## 签名安全

- 签名覆盖 HTTP 方法、路径、查询、关键头、正文摘要和时间戳。
- 请求包含短有效窗口和 nonce/请求 ID，防止重放。
- Key ID 只用于定位验证材料，不作为授权主体。
- 日志不得记录 Secret、完整签名或可复用 Authorization 头。
- 服务器时钟偏差和规范化算法必须文档化。

## 根密钥

账号根身份的永久访问密钥具有极高风险。产品应默认不创建，并持续在安全报告中突出显示；确需恢复使用时要求强 MFA、短期启用、来源限制和独立告警。
