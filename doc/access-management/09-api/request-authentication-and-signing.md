# 请求认证与签名

管理 API 和业务 API 支持短期会话凭据与永久访问密钥签名。签名证明请求由持有 Secret 的主体构造，并保护方法、地址、关键头、正文和时间戳不被篡改；签名本身不授予业务权限。

## 凭据

- `Key ID`：公开定位符。
- `Secret`：签名秘密，只在创建或 STS 兑换时返回。
- `Session Token`：临时凭据必需，绑定角色会话与过期时间。
- `Scope`：日期、地域、服务和请求版本等派生上下文。

## 规范请求

```text
HTTP_METHOD
CANONICAL_PATH
CANONICAL_QUERY
CANONICAL_HEADERS
SIGNED_HEADER_NAMES
SHA256(REQUEST_BODY)
```

路径与查询使用确定的 UTF-8 编码和排序；头名转小写并规范空白。请求正文摘要覆盖实际传输内容。代理不得改变已签名字段。

## 待签字符串

```text
IAM-HMAC-SHA256
TIMESTAMP
CREDENTIAL_SCOPE
SHA256(CANONICAL_REQUEST)
```

签名密钥从 Secret 与 scope 逐级派生，最终对待签字符串计算 HMAC。服务端使用相同规范化算法重建并以常量时间比较签名。

签名通过规范请求、待签字符串和分层 HMAC 派生保护请求。[^1]

## 防重放

- 请求时间戳只能在有界时钟窗口内。
- 高风险写请求携带唯一请求 ID 或 nonce。
- 幂等键防止重试重复执行，但不替代签名重放保护。
- 临时凭据必须同时提供匹配的 Session Token。
- 已撤销或过期凭据即使签名正确也失败。

## Web 与联合认证

浏览器控制台使用安全会话 Cookie 和 CSRF 防护，不把永久访问密钥存入浏览器。OIDC/SAML 回调在认证服务完成协议验证后建立本地会话；下游产品只接收受信主体上下文或平台令牌，不直接解析任意外部断言。

## 错误处理

认证错误区分未知 Key ID、凭据失效、签名不匹配、时间戳过期、Session Token 缺失和来源网络不允许，但对无权调用者使用不泄露账号存在性的公开错误。服务端日志保留请求 ID 与凭据 ID，不记录 Secret、完整签名或令牌。

## SDK 要求

- 从受支持凭据链加载短期凭据。
- 自动刷新 STS 会话并在刷新失败时停止调用。
- 使用单调/同步时间构造时间戳。
- 不在异常和调试日志中打印秘密。
- 对已发送的可变请求体先固定字节再签名。
