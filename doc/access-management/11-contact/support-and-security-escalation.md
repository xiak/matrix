# 支持与安全事件协作

访问管理支持请求通常涉及凭据、账号恢复和策略内容。支持流程必须在帮助诊断的同时避免收集可复用秘密或绕过正常授权。

## 提交支持请求

提供以下非秘密信息：

- 账号 ID 和受影响地域。
- 请求 ID、决定 ID、事件 ID 或异步任务 ID。
- UTC 时间范围和问题发生频率。
- 产品、动作和脱敏资源引用。
- 主体类型、用户/角色的稳定 ID 和会话类型。
- 稳定错误码，不依赖完整错误文案。
- 期望行为、实际行为和最近的配置修订。
- 可公开的策略最小复现或策略版本 ID。

不得提交密码、AccessKey Secret、完整 Session Token、Cookie、MFA 种子、恢复码、未脱敏 SAML 断言或 OIDC 令牌。

## 严重等级

| 等级 | 示例 |
| --- | --- |
| 严重 | 大范围认证/授权不可用、跨账号数据暴露、根身份或签名密钥泄露 |
| 高 | 管理员全部锁死、撤销不生效、明确拒绝被绕过、审计大面积缺失 |
| 中 | 单个产品接入错误、策略传播超出目标、部分 API 持续失败 |
| 一般 | 使用咨询、配额申请、文档或界面问题 |

## 安全事件立即动作

1. 禁用受影响凭据或主体并撤销活动会话。
2. 对已知攻击路径施加有界明确拒绝或网络封锁。
3. 保存认证、承担、决定和业务操作事件，避免覆盖证据。
4. 轮换相关访问密钥、IdP 证书或服务签名密钥。
5. 使用决定 ID 追踪受影响动作与资源。
6. 完成修复后按最小权限恢复，并持续观察拒绝与异常使用。

## 支持访问

支持人员不获得默认账号访问。需要协助时，由账号管理员创建有时限、最小权限、可审计的支持角色；提升权限需要明确批准。会话结束或工单关闭后撤销信任和活动会话。

## 账号恢复

恢复根身份或全部管理员锁死属于独立流程，需要多因素所有权证明、冷却窗口、全程审计和完成后强制轮换。支持人员不能要求用户提供现有密码或 Secret 来“验证所有权”。
