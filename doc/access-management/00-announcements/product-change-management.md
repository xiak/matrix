# 产品变更与兼容性管理

访问管理处于所有业务请求的安全路径上。一次动作命名、资源粒度、凭据格式或策略求值语义的改变，可能同时影响控制台、API、自动化和跨产品调用，因此必须按安全协议变更管理，而不是普通界面发布。

## 变更类型

| 类型 | 示例 | 兼容要求 |
| --- | --- | --- |
| 安全加固 | 密钥格式升级、签名算法升级、登录保护增强 | 提供双轨验证窗口、影响查询、撤销与回滚程序 |
| 授权粒度升级 | 服务级升级为动作级或资源级 | 新动作默认不授权；原策略含义在迁移窗口内可解释 |
| 主体来源变更 | 企业目录接入方式、联合协议配置变化 | 稳定外部主体映射不能静默改变 |
| API 变更 | 字段、错误码、限流维度、版本升级 | 已发布版本在承诺期内保持协议兼容 |
| 产品接入变更 | 新增动作、资源类型、标签条件或角色 | 先注册能力声明，再开放产品入口 |

## 发布流程

1. **识别受影响契约**：主体、凭据、策略、角色、资源名称、条件键、API 和审计事件分别列出。
2. **生成影响清单**：查询使用旧契约的用户、密钥、角色、策略和业务产品。
3. **提供验证工具**：在正式切换前允许管理员模拟新语义、验证策略并定位不兼容配置。
4. **分阶段启用**：先接受新旧格式，再让新格式成为默认，最后停止旧格式；安全漏洞紧急处置除外。
5. **保留可追溯性**：授权决定记录实际使用的产品能力修订、策略版本和凭据版本。
6. **完成清理**：旧路径停止后删除兼容代码和配置入口，文档只描述仍受支持的行为。

## 公告内容

一份可执行的安全公告至少包含：影响范围、风险、行为变化、关键时间点、管理员动作、验证方法、回滚限制、审计查询和支持渠道。不得只描述控制台按钮变化，也不能以“无感升级”掩盖授权语义变化。

## 兼容原则

- 新增动作、资源或条件键默认不扩大任何主体的权限。
- 明确拒绝和权限边界的安全含义不得在小版本中弱化。
- 密钥与令牌升级不得要求同时暴露旧秘密和新秘密。
- 联合身份映射变更必须防止一个外部主体被映射成另一个主体。
- 审计事件 schema 可追加字段；改变既有字段含义必须发布新版本。
- 传播延迟、缓存刷新时间和不可逆操作必须在公告中量化。

API 密钥升级、企业目录接入变化和接口授权粒度升级都必须作为协议、安全与业务接入变更统一管理。[^1]
