# 业务授权接入架构

业务产品通过统一授权接入协议复用身份、策略和决定引擎，同时继续拥有自己的动作、资源、标签和业务状态。接入不是在网关增加一个“已登录”检查，而是把每个业务 API 映射到可验证的授权语义。

每个接入产品公开控制台支持、标签授权、授权粒度、IP 限制等信息，并为具体 API 列出动作分类和资源范围。[^1][^2]

## 责任分配

| IAM 负责 | 业务产品负责 |
| --- | --- |
| 主体、组、角色和会话 | 业务资源及其生命周期 |
| 策略、边界和护栏 | API 到动作的映射 |
| 通用条件和策略求值 | 资源 ID、层级与所属账号解析 |
| 产品能力注册与校验 | 产品专用条件与资源标签读取 |
| 授权决定与解释 | 决定允许后的业务规则与事务 |
| 认证、角色承担与决定审计 | 业务执行结果审计 |

## 接入组件

### Authorization Profile

版本化声明产品 ID、动作、资源类型、条件键、授权粒度、标签能力、角色能力、列表语义和兼容规则。策略只能引用当前或兼容修订中存在的词汇。

### Action Resolver

将 HTTP/gRPC/消息操作映射为一个或多个稳定 IAM 动作。映射由代码和契约测试维护，不能根据路由名称在运行时猜测。

### Resource Resolver

从经过验证的请求和业务存储解析规范资源引用、所属账号、父子资源和授权属性。客户端提供的账号或标签只作为待验证输入。

### Policy Enforcement Point

在业务事务前调用授权决定。对于创建操作，使用拟创建资源范围与请求标签；对于修改或删除，读取当前资源并防止 TOCTOU；对于异步任务，在入队与执行时按协议选择重新授权或固定授权证据。

## 执行流程

1. Gateway 验证凭据并构造可信主体与网络上下文。
2. 产品识别业务动作并解析目标资源。
3. 产品构造 AuthorizationRequest，携带所用 Profile 修订。
4. IAM 验证动作/资源 schema 并求值策略。
5. 拒绝时产品不进入业务写事务。
6. 允许时产品执行业务不变量，并把 Decision ID 写入业务审计/outbox。
7. 异步任务记录最初决定和执行身份；需要持续授权的任务在执行时重新求值。

## 特殊接口

### 创建资源

资源尚不存在时，以父资源、拟创建类型、请求标签和目标账号授权。创建事务必须保存已经授权的标签，避免授权与写入分离。

### 列表与搜索

产品声明整体授权或服务端资源过滤。高基数列表优先把可安全下推的账号、资源层级和标签条件编译到查询；不能把全部资源返回后仅在前端隐藏。

### 批量操作

逐资源求值并返回逐项结果，或在原子批量事务中任何拒绝导致整批拒绝。批量接口不使用首项代表全部。

### 长任务

任务提交者、执行服务角色和目标资源权限分别记录。若任务在未来持续产生副作用，使用服务角色的当前权限；若要求提交时授权快照，产品必须声明快照范围、时效和撤销方式。

## 错误边界

- 认证失败由认证层返回，不伪装成业务不存在。
- 授权拒绝使用稳定公开理由码，不泄露其他账号资源。
- 未知动作、资源类型或 Profile 修订视为接入错误并关闭失败。
- IAM 超时不默认允许；产品可以对明确只读、缓存安全的操作配置受控降级。
- 业务规则失败与授权拒绝分开记录。

## 接入验收

每个产品至少验证一个服务级、动作级、资源级或声明不支持的真实路径；同时覆盖读取、写入、创建、列表、批量、跨账号、标签条件、伪造身份头和审计关联。
