# 产品概述

访问管理（Identity and Access Management，IAM）是云平台的统一身份与授权控制面。它回答四个问题：调用者是谁、能够承担什么身份、允许对哪些资源执行哪些动作、该决定如何被解释和审计。

IAM 不替代业务产品。计算、存储、数据库、网络、开发工具等产品仍然拥有自己的资源生命周期和业务规则；IAM 通过统一主体、策略语言、角色会话和授权决定，把这些产品连接到同一安全底座。每个业务产品同时声明自身支持的授权粒度和接口资源。[^1][^2]

## 产品目标

- 为人员、应用、云服务和外部身份提供统一主体模型。
- 以最小权限为默认，让权限可组合、可收窄、可撤销。
- 用短期会话代替跨边界分发永久凭据。
- 让每个业务产品拥有动作与资源语义，同时复用同一个策略求值系统。
- 为每次允许与拒绝生成可解释、可关联的安全证据。
- 支持单账号、跨账号、企业联合身份和属性化授权等治理模式。

## 核心使用者

| 使用者 | 主要诉求 |
| --- | --- |
| 账号所有者 | 建立管理边界、恢复访问、设置全局安全策略 |
| 组织管理员 | 管理人员、组、角色、策略、身份提供商和权限边界 |
| 普通用户 | 使用独立身份登录，在授权范围内操作资源 |
| 外部协作者 | 通过受控身份或角色访问指定账号资源 |
| 工作负载 | 用服务身份或短期角色会话调用 API |
| 业务产品 | 声明动作、资源、条件与角色能力，并执行授权决定 |
| 安全与审计人员 | 分析有效权限、凭据状态、角色承担和操作记录 |

## 核心能力

1. **身份管理**：账号、用户、外部协作者、企业目录用户、服务身份和通知联系人的生命周期。
2. **认证安全**：密码、MFA、登录限制、操作保护、会话管理、访问密钥和签名认证。
3. **授权管理**：用户组、托管策略、自定义策略、策略版本、资源策略、条件和策略分析。
4. **委派访问**：角色、信任策略、安全令牌服务、服务角色、资源角色和角色审计。
5. **身份联合**：SAML、OIDC、用户 SSO、角色 SSO 与企业身份提供商。
6. **权限治理**：权限边界、ABAC、资源标签、多账号治理、闲置身份与凭据分析。
7. **业务接入**：产品能力声明、动作/资源映射、授权执行点和统一决定接口。
8. **审计与诊断**：允许/拒绝解释、无权限诊断、操作记录和安全分析报告。

## 产品边界

IAM 管理访问关系，不管理资源本身。它可以保存资源的规范引用和授权属性，但资源是否存在、资源层级如何变化、一次业务操作是否成功，均由资源所属产品决定。IAM 也不把企业 HR 档案、通知内容、计费账单或工单作为授权事实；这些系统通过稳定身份映射或受保护接口协作。

## 安全原则

- 未被明确允许的请求默认拒绝。
- 任一明确拒绝优先于允许。
- 长期身份与临时角色分离，信任关系与权限关系分离。
- 权限边界只能收窄权限，不能产生允许。
- 凭据秘密最小暴露，短期、可轮换、可撤销。
- 业务产品不能绕过统一授权执行点信任客户端声明。
- 授权决定必须保留主体、原始主体、策略版本、资源与上下文证据。
