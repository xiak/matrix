# 创建用户并授权

用户入职由身份创建和权限授予两个独立步骤组成。创建用户只建立可管理的人员主体；用户必须获得策略、组成员关系或角色承担权限后才能访问资源。

## 创建用户

1. 选择用户来源：本地用户、企业目录用户或外部协作者。
2. 填写稳定登录标识和必要显示信息。
3. 选择访问方式：控制台、编程式访问或两者。
4. 为交互式用户配置一次性激活，不发送可长期使用的明文密码。
5. 为编程式访问选择短期令牌；确需访问密钥时再创建。
6. 配置 MFA、登录来源和敏感操作保护。
7. 添加用于治理的受控主体属性或标签。

## 授权方式

| 方式 | 使用场景 | 维护特征 |
| --- | --- | --- |
| 加入用户组 | 多名人员共享职责 | 组策略集中变更 |
| 直接绑定策略 | 少量用户的例外权限 | 需定期清理，避免长期例外 |
| 允许承担角色 | 临时、跨账号或高权限任务 | 会话有时限并保留承担者 |
| 属性策略 | 人员和资源规模较大 | 依赖可信属性与标签治理 |

访问方式、策略绑定、用户标签和最终审阅应在同一入职流程中统一校验。[^1]

## 最小权限步骤

1. 从具体工作任务列出需要的业务动作。
2. 确定动作作用的资源类型与范围。
3. 添加来源网络、时间、认证强度或标签条件。
4. 使用策略模拟验证允许路径和邻近拒绝路径。
5. 授予用户组或角色，而非复制到大量用户。
6. 登录测试账号验证控制台和 API 的实际结果。
7. 记录权限所有者与复核日期。

## 安全检查

- 用户未获任何允许时保持默认拒绝。
- 新用户不能修改自己的组、权限边界或授权属性。
- 第一次登录强制完成凭据更新和 MFA 注册。
- 访问密钥秘密只展示一次。
- 入职事件记录创建者、授权者、策略版本与用户来源。
