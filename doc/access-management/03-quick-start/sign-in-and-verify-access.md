# 登录并验证访问

访问管理提供账号定位、用户认证、身份选择、MFA、会话建立和授权验证的完整登录链路。登录成功仅证明主体身份，不代表对所有业务产品拥有权限。

## 登录流程

1. 用户选择所属账号或使用账号专属登录地址。
2. 输入本地凭据，或跳转到企业身份提供商。
3. 系统校验账号状态、用户状态、登录来源和风险规则。
4. 按策略完成 MFA 或其他二次校验。
5. 外部协作者具有多个身份时，显式选择本次访问身份。
6. 系统建立有绝对期限和空闲期限的会话。
7. 控制台按授权结果展示入口；每个业务 API 仍独立授权。

用户可以通过“用户名@账号标识”定位账号；拥有多个协作身份时，需要显式选择本次访问身份。因此认证主体与访问身份是两个不同概念。[^1]

## 首次访问验证

使用新用户至少验证四条路径：

- 可以读取被授予的资源。
- 可以执行明确授予的写动作。
- 不能访问相邻但未授予的资源。
- 不能执行策略中未包含的敏感动作。

拒绝响应返回请求 ID、动作、资源摘要和可公开理由码。管理员可使用这些信息运行无权限诊断，但普通用户不应看到其他策略或主体信息。

## 会话安全

- 登录后重新生成会话标识，防止会话固定。
- Cookie 使用 Secure、HttpOnly 和适当 SameSite 策略。
- 高风险管理操作要求新鲜的 step-up 证据。
- 用户禁用、密码重置、MFA 恢复或安全事件可以撤销现有会话。
- 退出登录使当前会话失效；全局退出撤销该主体的所有交互式会话。
