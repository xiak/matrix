# 基于属性与标签的访问控制

基于属性的访问控制（ABAC）使用主体、会话、资源、请求和环境属性表达权限。它把权限与业务属性关联，并使用用户/角色标签、会话标签、资源标签和请求标签实现规模化访问控制。[^1][^2]

## 属性模型

| 属性来源 | 示例 | 可信写入方 |
| --- | --- | --- |
| 主体属性 | 部门、项目、岗位、成本中心 | 身份管理员或企业目录 |
| 会话属性 | 当前项目、任务、环境、认证强度 | STS 与受信 IdP 映射 |
| 资源标签 | 项目、环境、数据级别、所有者 | 资源产品与受权资源管理员 |
| 请求标签 | 创建资源时拟写入的标签 | 调用者输入，产品验证后提交 |
| 环境属性 | 来源网络、时间、设备风险 | Gateway 与安全平台 |

每个属性键在注册表中声明命名空间、类型、所有者、允许值、敏感性和可用操作符。

## 典型策略

### 项目匹配

允许用户访问与其项目属性相同的资源。

### 环境分离

开发角色可以管理 `environment=dev`，生产角色只能读取 `environment=prod`；生产写操作需要 MFA 和短期高权限角色。

### 创建时强制标签

创建请求必须携带 `project` 和 `owner` 标签，且 `request.tag.project` 等于主体项目。资源和标签在同一事务提交。

### 角色会话标签

企业 IdP 将当前任务或团队映射为允许的会话标签；角色信任策略限制可传入的键和值，权限策略再使用这些标签。

## 防提权规则

1. 修改用于授权的主体属性是身份管理动作。
2. 修改或删除资源授权标签是独立资源管理动作。
3. 标签写权限不能由同一标签条件自我授予。
4. 请求标签在资源创建前求值，缺少必需标签时关闭失败。
5. 会话标签必须通过 IdP 映射与角色信任的双重白名单。
6. 标签键缺失默认不匹配；空字符串不等于公共范围。
7. 标签继承由产品显式声明，不能从父资源名称推断。
8. 列表接口在服务端执行属性过滤。

## 仅匹配标签键

有些治理规则关注“资源是否带有某个标签键”，不限制具体值，例如禁止删除任何标记为 `protected` 的资源。条件系统应区分键存在、键值等于和集合包含，避免用通配字符串模拟。

## 规模与缓存

高基数 ABAC 需要把安全可下推的标签谓词编译到产品查询，同时固定属性修订和标签读取快照。资源标签变化应使相关决定缓存失效；缓存键包含账号、主体、动作、资源/标签修订和会话属性摘要。
