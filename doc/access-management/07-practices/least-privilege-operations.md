# 最小权限运营

最小权限不是一次性写出更短策略，而是从身份建立、任务授权、凭据使用、监控、复核到撤销的持续运行机制。

## 身份基线

- 账号所有者只用于恢复和不可委派操作。
- 每名人员使用独立用户或企业联合身份。
- 稳定职责通过用户组表达，临时或高权限任务通过角色表达。
- 工作负载使用资源身份和短期会话，避免共享永久密钥。
- 管理员、联合配置和凭据操作启用 MFA/step-up。

## 授权设计

1. 从业务任务列出所需动作，而不是从预置管理员策略开始删减。
2. 将动作限制到明确资源类型、账号、地域和资源路径。
3. 使用来源网络、时间、认证强度、标签或外部 ID 等可信条件。
4. 把通用职责放入托管策略并通过组或角色复用。
5. 用权限边界约束可以自行创建策略的委派管理员。
6. 对组织级禁区使用明确拒绝，避免大量重复排除规则。
7. 发布前模拟允许路径、邻近拒绝路径和资源列表行为。

## 凭据运营

- 优先使用短期会话；永久访问密钥只用于兼容场景。
- Secret 只展示一次，并由秘密管理系统注入应用。
- 密钥按无中断流程轮换，先验证新密钥再禁用旧密钥。
- 对永久密钥应用来源网络限制并观察最后使用。
- 用户禁用、泄露或离职时同时撤销会话、密钥和角色承担。

## 权限复核

复核以“主体—来源—策略—角色—资源—最近使用”视图为单位：

- 谁拥有该权限，来自直接策略、组、角色还是资源策略；
- 权限是否被边界或护栏收窄；
- 允许的动作在统计窗口内是否实际使用；
- 是否存在过宽通配符、无条件 PassRole 或跨账号信任；
- 负责人是否仍认可业务理由与到期时间。

没有使用记录只是收窄候选，需要结合审计水位、批处理周期和灾备用途确认。

## 变更控制

策略变更使用不可变版本和权限差异；新增允许、移除拒绝、放宽信任和边界解绑属于高风险。变更记录原因、审批、策略修订、传播状态与回滚版本。

## 事件响应

怀疑凭据泄露时：优先禁用密钥或主体、撤销会话、添加有界明确拒绝，随后查询最近使用和业务审计，最后轮换受影响秘密并恢复最小权限。紧急控制不依赖普通创建 API 的限流预算。

安全实践同时覆盖根身份保护、MFA、最小权限与凭据轮换。[^1][^2]
