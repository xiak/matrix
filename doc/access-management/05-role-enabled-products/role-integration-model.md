# 业务角色接入模型

支持角色的业务能够以受信服务或资源身份承担角色，并用临时凭据代表账号访问其他产品。角色接入适用于计算、容器、存储、网络、数据库、安全、数据、AI、企业应用、开发运维和物联网等产品类别；类别本身不改变统一的信任与会话协议。

角色能力由 IAM 提供统一机制，并由各业务产品声明具体用途。[^1]

## 接入参与者

- **业务产品**：发起角色承担，拥有任务或资源生命周期。
- **服务主体**：在 IAM 中注册的稳定产品身份。
- **账号管理员**：批准角色、权限范围和业务产品使用关系。
- **角色**：保存信任策略、权限策略、边界和会话设置。
- **STS**：验证信任并发行短期凭据。
- **目标产品**：验证临时凭据并按角色权限授权 API。
- **审计系统**：关联角色承担、源业务任务和目标产品操作。

## 产品角色声明

一个支持角色的产品发布以下契约：

| 字段 | 含义 |
| --- | --- |
| `service_principal` | 可写入角色信任策略的稳定服务主体 |
| `role_modes` | 自定义服务角色、服务关联角色、资源角色 |
| `purpose` | 产品为何需要代表账号访问其他产品 |
| `required_actions` | 最小目标产品动作集合 |
| `resource_scope` | 可限制的目标资源类型和关系 |
| `pass_role_action` | 管理员把角色传递给产品所需动作 |
| `session_duration` | 产品支持和建议的会话时长 |
| `source_binding` | 任务、资源、项目或账号绑定方式 |
| `lifecycle` | 创建、更新、使用、删除和阻塞条件 |
| `audit_fields` | 源任务、源资源和承担会话关联字段 |

## 自定义服务角色流程

1. 管理员创建角色并信任目标服务主体。
2. 管理员绑定产品任务所需的最小权限。
3. 创建业务任务时传入角色 ID。
4. 业务产品验证调用者的 PassRole 权限和角色适用性。
5. 产品以服务主体承担角色，STS 发行短期会话。
6. 产品用临时凭据调用目标产品。
7. 审计关联原始管理员、业务任务、角色会话和目标操作。

## 服务关联角色流程

产品能力启用时请求创建受控角色。IAM 校验产品注册的信任与权限模板，管理员确认后创建。模板升级新增权限时必须重新评估；产品不能自行把角色权限扩展到声明之外。删除前产品返回仍依赖该角色的资源，依赖清零后才完成删除。

## 资源角色流程

业务资源创建时绑定角色。运行时使用资源证明向本地身份端点请求会话，端点校验资源 ID、租户、运行环境和角色绑定。凭据只对该资源工作负载可见，并自动在到期前轮换。

## 安全要求

- 服务主体由平台注册，不能用普通字符串冒充。
- 信任策略限制来源账号、产品、资源或任务。
- PassRole 与创建业务任务分别授权。
- 产品不保存角色永久密钥，只缓存短期凭据。
- 会话名称和 source identity 可关联真实任务。
- 角色权限新增、信任放宽和服务模板变化生成高风险事件。
- 目标产品始终按会话重新授权，不只相信源产品的成功响应。

## 接入验收

产品必须证明：角色创建与删除、允许与拒绝承担、短期凭据刷新、PassRole 越权防护、任务/资源绑定、凭据隔离和跨产品审计链路均可运行。
