# 服务规格、配额与容量

访问管理的服务规格由身份容量、策略复杂度、角色与联合容量、凭据容量、API 吞吐和变更传播目标构成。部署必须发布明确数值；管理员应能通过账号摘要和配额 API 查询当前使用量、上限与可调整项。

## 配额维度

| 能力 | 典型配额 | 超限行为 |
| --- | --- | --- |
| 用户 | 每账号用户数、每用户组数、每用户访问密钥数 | 创建失败，不影响既有身份 |
| 用户组 | 每账号组数、每组成员数、每用户所属组数 | 成员变更原子失败 |
| 策略 | 自定义策略数、单策略字符/statement 数、版本数 | 发布失败，旧默认版本继续生效 |
| 绑定 | 每用户/组/角色的策略数、每策略实体数 | 新绑定失败，既有绑定不改变 |
| 角色 | 每账号角色数、信任主体数、最大会话时长 | 创建或承担请求返回明确错误 |
| 身份提供商 | SAML/OIDC 提供商数、映射规则数、元数据大小 | 配置校验失败，不替换有效配置 |
| 临时会话 | STS 发行速率、并发会话、令牌大小 | 限流或缩短请求范围，不降级为永久密钥 |
| 标签与属性 | 每主体/角色/资源的键数、键值长度 | 写入失败，不截断授权属性 |
| API | 按 API、地域、账号、主体的请求速率 | 返回可重试限流错误和等待提示 |

用户、角色、组、自定义策略、策略绑定等数量限制与逐接口频率限制共同构成服务规格；配额既是存储容量，也是安全和控制面稳定性契约。[^1][^2]

## 配额原则

- 超限必须关闭失败，不能静默丢弃策略 statement、组成员或标签。
- 安全收紧操作应与普通创建操作分开预算，避免限流阻止紧急禁用密钥或用户。
- 批量 API 按实际处理实体计量，并返回逐项结果或原子失败语义。
- 配额调整保留操作者、原因、旧值、新值和生效时间。
- 删除对象后，配额释放与审计保留分离；历史事件不因释放配额而消失。

## 容量规划

规划访问管理容量时，除主体数量外还要估算：

1. 每次决定需要加载的策略与绑定数量。
2. 产品动作和资源目录的规模与发布频率。
3. 登录、API 签名验证和 STS 的峰值吞吐。
4. 资源标签查询与列表过滤的基数。
5. 授权决定、认证和管理事件的审计写入量。
6. 多地域缓存数量及策略传播速度。

PDP 的性能测试应覆盖最坏合法策略，而不是只测单一允许规则。容量保护不能改变默认拒绝、明确拒绝优先或权限边界语义。

## 一致性目标

服务规格必须分别声明：管理写入确认时间、策略传播目标、凭据撤销目标、会话失效目标和审计可查询延迟。身份或策略跨地域复制可以最终一致，但安全撤销应拥有更短的优先传播通道，并允许查询各执行点的当前修订。
