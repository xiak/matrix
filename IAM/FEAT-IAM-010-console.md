## 详细设计

### 真实管理快照与隔离体验

沿原 repository → provider → scene → renderer 接入，不从策略名称、列表读取成功或 MOCK 求值结果推导权限。当前身份决定可请求的目录；目标详情和每项操作消费准确 action/resource 的服务端 capability。缺失、重复、外来或未知能力使响应失效，不能猜成管理员许可。可用性只避免死胡同点击，实际请求仍由 IAM 重新鉴权。

进入 IAM 路由时，目标路由标题和固定页面语义必须同步挂载，不等待 CurrentIdentity 或场景组合读取。只有权威数据拥有的区域可以进入加载态：User、租户账号、Group、Policy 和 Role 目录使用表格区域骨架；总览、详情和工作流使用各自内容区域的稳定几何，不得用一块整页骨架替换 Header、侧栏、标题或整个内容画布。已有可信场景的刷新继续保留旧内容并标明更新中；首次读取失败显示局部不可用而不是空成功，也不得回退隔离 MOCK。具体路由承载、延迟占位和跨服务切换由 FEAT-007 的共享外壳契约拥有。

Account/RootIdentity 与日常 User 分开。主身份展示为受保护的账号所有者，不因没有普通策略附件显示为未授权，也不进入普通 User 的授权、禁用、删除或边界设置流程。按照 IAM 的固定目标架构 `204b1d55`，Root 的账号管理与恢复权能来自封闭的 tenant-owner capability catalog，而非通配策略或平台角色；所有者身份不自动证明任意业务资源操作可用，具体按钮仍按已验证的当前 capability 和服务端动作结果决定。此目标架构尚未替代当前 LIVE 权威。创建 User 不开通另一个 Account。

租户账号目录与 User、Group、Policy 目录使用同一原生表格契约。桌面保留列式比较，小屏改为带字段标签的纵向行，必须同时呈现租户稳定 ID、主账号登录名、主账号别名与状态；不能依靠横向裁切隐藏账号身份字段，也不增加逐行操作列。对象名称继续进入内容区详情，生命周期动作由详情页准确 capability 决定。

`AccountPolicy`、`PolicyDirectory` 和 `UserPolicyAttachment` 替代旧的内置角色投影；新 User 默认无业务授权。Tenant/installation 策略目录独立读取与授权，各为稳定 ID 有序、最多 256 项的完整元数据快照；仅 403 是局部不可用，其他失败关闭对应真实场景。缺少 installation 策略元数据时展示稳定 Policy ID，不隐藏有效直接附件，也不由元数据制造正文、继承、边界或最终允许结果。

当前在线授权权威只有 `Policy`、`PolicyVersion` 与 `PolicyAttachment`；历史 `RoleBinding` 标识只服务旧事实或迁移证据，不能形成兼容授权页、只读入口或第二套客户端模型。真正的 `Role` / `RoleSession` 拥有独立信任策略、承担检查与有界临时会话，不得与旧枚举角色混淆。目标 MOCK 同样不再显示“平台内置角色”并行入口。

签名目录 continuation 原样传递，不当作资源 ID 或许可。搜索、分页和全选明确覆盖已加载记录，不捏造全局总数，也不为装饰表格逐行查询 User。同账号缓存摘要仅装饰成员关系中的 User ID，不证明存在性或操作权限。组成员关系、直接组附件、直接 User 附件与 policySources 保留各自来源和修订。

策略目录保留桌面列、搜索、筛选、分页和至多 30 项的当前结果选择。窄容器下以同一原生表格的带字段标签纵向行呈现策略元数据；带选择列的表格须在堆叠后仍露出本页全选控件，不能把它随视觉隐藏的列标题一起移除。没有产品/级别值的 MOCK 自定义策略只在小屏省去空字段，不把“—”误当权限分类。LIVE 元数据目录沿用相同响应式契约，数据归属、授权与正文懒读取规则不因布局变化。

用户目录在桌面保留身份、类型、访问方式、策略来源和状态列；小于或等于 `560px` 的表格容器把同一原生行堆叠为可读的纵向信息，不要求横向拖动。本页全选保持可见，行选择框、用户身份与状态位于行首，访问方式和策略关联带字段标签；主身份继续独立于普通 User 表格展示。响应式排版不得改变本页选择范围、能力门控或分页语义。

User 批量操作只在 repository 明确提供对应能力时出现，最多覆盖当前已加载和筛选出的 30 个普通 User；主身份不进入选择集。添加用户组与直接关联策略是追加关系的内容区“选择 → 审阅 → 提交”流程，必须显示准确目标并保留原有关联；取消保留目录选择并把焦点交还稳定的“更多操作”，确认完成后等待目录权威刷新再清空选择并回到“创建用户”。启用、禁用和删除继续使用短、聚焦的确认 Dialog，不能借内容区改造弱化生命周期确认。当前只有隔离 MOCK repository 实现该批量命令；不得因此增加 LIVE 适配器、推断后端 Action 或声称真实授权已完成。

从 LIVE User 目录进入详情时，目录已经验证的目标身份摘要立即组成稳定的详情框架；登录名、显示名、限定登录名、User ID、Account ID 和目录状态在精确详情读取期间保持可见。只有依赖 `UserAccess` 的数据区显示延迟骨架，任何编辑、授权、状态、凭据或删除操作都必须等精确详情及其 capability 成功返回后才能出现。目标读取失败保留该只读定位上下文并原位重试同一个 User，不回退 MOCK、不把目录摘要提升为写权限，也不重载 Header、侧栏或整个 IAM 场景；离开或重试后的迟到结果不能覆盖当前读取代次。

关联/撤销携带所选 Policy 或当前附件修订；选择后 Policy 变化须清空并显式重选。新建组只创建组；成员关系和直接策略变更各为一个版本化关系命令。不确定结果保留同一 requestId 和完整 payload，冲突读取最新状态、关闭旧编辑并要求新的意图。目录标题、搜索、新建入口以及详情标题/返回路径同步呈现，只有组目录行、组事实和成员关系等远端数据区延迟骨架或局部失败；快速成功不能先闪出空目录。成员和策略的选择、审阅与提交替换组详情的内容主体，不使用遮蔽页面的大型 Dialog；返回详情须保留来源页签并把焦点交还来源操作，若权威重读使该操作暂不可用则回退到稳定详情操作。删除仍使用短、聚焦的破坏性确认。组不作为登录身份、资源所有者或最终授权结果。

User 直接策略关联先选择、再在当前内容区审阅目标 User、策略作用域、默认版本及目录修订；撤销则审阅精确附件 ID、修订与影响范围。平台安装和租户策略分别按服务端返回的准确 capability 提供入口，目录可见不代表可授权。两种变更共享同一 Account/操作者绑定的关系意图，互斥且冻结 requestId 与完整输入；切换 IAM 列表、详情或其他路由后仍保留原审阅，另一个 User 的新关系操作被锁住，旧 Session 的迟到结果不能更新新 Session。首次关联提交仍校验当前目录修订；LIVE 撤销走接收原 requestId 与附件修订的专用 API，不再通过通用命令自动生成新请求号。网络结果不明时客户端在 `sessionStorage` 只保留原 Account、操作者、requestId 和非秘密输入摘要；同一 Account/操作者刷新或正常重新登录后恢复提醒，外来、畸形或不同操作者记录失败关闭，凭据、策略正文和任何 Secret 不进入持久存储。结果未知后页面只允许检查原请求的不可变完成记录，不再提供写请求重放或生成新 requestId；精确完成记录确认后仍保留提醒，直到当前对象完成权威重读并由操作者结束审阅。

该只读完成查询的完整契约来源固定为 `8abbea36da422fdb758233b68221ad8139b00904`，生产实现固定为 `2e18b09293adf9bdf7ffbd3fa0042de566f76e9b`。Verification `37540304178` 中 storage、recovery-storage、roles 及 authority-runtime 内部测试已有成功证据，但外层 20 分钟作业被取消，未取得可继承的成功终态；因此这里只固定 wire 和客户端解释，不能据此接受 LIVE 发布。当前累计源码和 receipt 持久性核对证据为 `7b9b5061fa17e65b387ac42385b3d980d009b4fb`；它只加固 CI selector、替换偶然测试快照并修正 OpenAPI 描述，没有改变 receipt SQL/HTTP 运行语义，Verification `37547361514` 仍在运行，不能写成 success 或 Accepted。客户端统一调用 `GET /v1/policy-attachment-changes/by-request/{requestId}`，只在路径发送原 requestId；Account、actor、target、policy、scope、installation 和 operation 都只是本地响应绑定预期，不能成为请求 selector。CREATE 只接受 `USER`、`GROUP`、`ROLE` 精确目标，`SERVICE_ACCOUNT` 必须拒绝；完成记录必须精确绑定目标、Policy ID／版本及返回附件。REVOKE 完成记录不携带 target，必须精确绑定原 attachmentId、预期附件版本以及撤销 ID／版本／时间。200 只有在严格解码互斥的 CREATE/REVOKE `PolicyAttachmentChange` 并核对原 Account、操作者、requestId、操作和全部冻结输入后，才显示不可变完成证据并解除关系锁；404、403、5xx、网络或协议错误都继续保持未知，401 只使当前登录失效，同一操作者重新登录后仍可检查原 requestId。

User、Group 与 Role 的直接策略关系共用上述 by-request 恢复协议。Group/Role 页面在发出写请求前冻结非秘密输入并按 Account、操作者和准确目标保留标签页级提醒；页面重建或同一操作者重新登录后自动回到对应内容区工作流，不同操作者、畸形或外来记录失败关闭。结果未知时主动作只能查询原请求，不生成新 requestId、不会自动或隐式重放写请求；查询确认后仍须权威重读当前对象才关闭提醒。Receipt 在当前保留数据库中的无 TTL、长期不可变历史及 UNKNOWN 终态由 IAM FEAT-002 唯一拥有，并固定于 `3aede305d55190c068c90ad890994f0af461be1e`；本 FEAT 只消费其客户端后果：同一 actor 的新正常 LOGIN_SESSION 在 receipt 仍存在且拥有 read action 时可以继续查询，403 只提示恢复读取权限，404 永远不证明原写回滚，且当前没有可调用的人工解锁或按当前关系目录裁定原命令结果的 API。恢复较早备份只会恢复该备份时点已经存在的 receipt，不会保留或合成之后的 completion；此时查询得到 404 仍必须保持 UNKNOWN。当前关系目录存在或不存在、后继撤销/重建、策略退休、主体状态、旧命令无 receipt 或本地提醒丢失都不能证明原写入成功或失败；直接附件完成记录也不等于最终 Allow。隔离 MOCK 不伪造真实 receipt，测试注入的完成样例只验收界面状态。真实 IAM 进程的丢回包、换 Session 与浏览器闭环仍是发布前门槛。

管理员重置 User 密码的原请求结果查询按 IAM 固定来源 `21b3de3a3034713fd4ddfa08ec654bb648694bc8` 建立严格只读客户端；其独立 Verification `36462106282` 尚未通过，不能因此接受当前 UX 分支为 LIVE 安装候选。提交响应不明时保留原 Account、操作者、User、requestId 和预期用户版本，清除密码输入并锁住再次重置。页面只在原操作者当前有效 Session 下显式查询原请求；200 必须精确绑定原五元组并校验版本递增，才显示“原请求已提交”，不宣称临时密码目前有效或审计投递成功。404、401/403、5xx、传输或协议错误都继续显示结果未知，不自动重发 POST、生成新 requestId 或允许一键解除锁定；只有确认 200 后可结束提醒。隔离 MOCK 没有可信完成日志，默认查询只返回未知；测试可注入完成样例验证界面状态，但不代表真实 IAM 已确认。真实进程查询与 POST 丢回包后的浏览器闭环仍待后端原子整合验收。

隔离 MOCK 的 User 关系向导与上述审阅保持同一信息顺序：目标登录名与稳定 ID、当前 Account、关系类型，以及新增/移除/保留对象。策略行展示稳定策略 ID、系统或自定义类型和当前默认版本；用户组行展示稳定组 ID。MOCK 策略模型没有真实 installation/tenant 作用域修订或权威附件响应，因此不得从名称补造这些字段、把预览变更说成真实授权，或承诺最终 Allow。说明只在向导标题区出现一次，不在审阅列表重复占空间。

真实组详情的成员关系是独立读取区：首次读取才使用局部骨架；组变更后的重新读取保留已验证的旧行并标明更新中，期间关闭关系操作，避免整表先清空再闪回。若权威组详情读取失败则关闭旧详情和操作；若仅成员重读失败则隐藏旧行并提供局部重试，不能把过期关系当作当前成功结果。

Role、身份提供商、联合身份和企业账号均为详情优先的管理对象：目录名称只负责打开准确详情，编辑、状态、导入与危险操作统一由详情标题栏承载。目录不重复逐行操作列；小屏由公共页面操作菜单收纳次要命令。User 独有的批量选择仍按其单独契约处理，不能据此向其他目录伪造批量后端能力。访问密钥不是 Account 级全局目录；它必须先定位 same-account User，再读取和管理该 User 自己的密钥集合。

高级体验仓库仍只通过一键 MOCK 入口选择。尚未接入的策略编写、SSO 或模拟器明确说明；Role 管理只在固定契约存在时开放对应 LIVE 动作，访问密钥页面同样只在存在固定 HTTP 能力时使用 LIVE per-User 适配，否则只允许显式 MOCK 工作区继续展示体验。任何真实失败都不调用体验仓库兜底。UI 原型与后端固定契约逐片衔接，不能据此发布一个尚未整合后端的安装版本。

身份安全概览与尚未接入的来源继续归 IAM-009 S4 的真实治理契约所有。概览只从隔离体验仓库派生本地建议，明确区分“需复核、已配置、不适用、状态未知”，且把设置开关与认证器绑定证据分开。活动区按成功登录、Key 使用、Role 活动与业务结果分别呈现；只有当前 MOCK Session 的实际签发可作当前身份的登录样例，普通操作事件不能冒充成功登录，Key 创建/修改时间、Role 或 RoleSession 存在及 IAM Allow 不能分别冒充真实使用或业务成功。缺少认证器、最近使用、完整采集窗口或来源水位时必须为未知，不能猜成 `false`、安全、闲置或从未使用。账号安全报告已经严格接入 `POST /v1/account/security-reports`、`GET /v1/account/security-reports/{reportId}` 与 `GET /v1/account/security-reports/{reportId}/content`；它只支持创建、按 ID 读取和下载，未建立真实报告目录、风险分、后台任务或自动处置能力。保留的 MOCK 报告目录只是本地搜索、筛选、状态和到期样例，不能解释成服务器持有这些报告。

### 本人安全通知地址的固定客户端接入

非体验仓库的设置页按 `f5cec0e132ad18900d9a5a5629eae04fda4817f1` 消费本人第一条安全通知地址及验证意图：读取当前联系地址、以当前密码和稳定 requestId 发起八位邮件验证码、读取原验证意图并确认。请求不接受 Account/User/SMTP/模板选择器，响应必须重新绑定当前 Account、User、地址、验证 ID 与 requestId；额外字段、非法状态、错误归属或不满足精确十分钟生命周期均失败关闭。

该地址只承载安全通知，不是登录名、恢复通道、MFA 因子或授权依据。首次绑定仍是独立验证意图；已经验证的本人地址可以按 IAM-012 S1c 的固定替换契约更换，但不提供删除或管理员代绑。替换必须以当前密码、已绑定 TOTP、原 factor revision、联系人资源版本和规范化候选地址取得 purpose-bound StepUp；旧地址在候选地址验证码确认成功前始终权威，确认本身就是唯一原子提交点。联系地址与验证意图保持分离：首次意图 `PENDING` 时地址仍为 `NONE`，替换意图 `PENDING` 时旧地址仍为 `VERIFIED`。投递观察按后端事实显示，`ACCEPTED` 只接受精确 SMTP `250`，且只表示邮件服务器接受，不能呈现为已投递、已送达或已读。任何网络、5xx、协议或 404 结果都不得回退 MOCK。

设置页固定标题、边界说明和卡片外壳同步渲染，只有联系地址和认证器数据区使用局部加载反馈；确认或刷新数据时不卸载整个设置页。DEV 一键体验继续使用独立、明确标记的页内 MOCK，不调用 IAM、不写浏览器存储，也不发送真实邮件。MOCK 的已验证地址属于当前内存工作区，不属于一次组件挂载；路由切换和正常重新登录保留它，退出或重置体验才清除。确认写入失败时仍待验证，不可闪现成功并允许绑定因子。

### 本人 MFA 生命周期的固定客户端接入

本人首次 TOTP 绑定同样消费 `f5cec0e132ad18900d9a5a5629eae04fda4817f1`。它只从当前有效的本人设置进入，必须先具有可信已验证安全通知地址，并用当前密码和当前 factor revision 发起五分钟 enrollment；因为此时不存在旧因子，界面不能要求一个不存在的旧 TOTP。首次 `APPLIED` 才能在当前内存流程显示 seed 与 provisioning URI，页面不调用外部二维码服务，也不把秘密放入 URL 或浏览器存储。

`EQUAL_REPLAY` 永不包含 provisioning；页面不显示验证码确认框，只允许取消仍处于 `PENDING` 的原流程，或在终态后使用新 requestId 重新开始。若首次 `APPLIED` 的秘密已从本地内存丢失，客户端不能尝试恢复或猜测密钥，必须取消/等待过期后重新发起。新 TOTP 确认成功就是绑定提交点；IAM 返回的十条唯一恢复码只在 SessionProvider 内存中一次显示，确认已保存后清除，并要求正常重新登录，不能把恢复材料的确认误作绑定提交。

已绑定因子的恢复码再生成消费固定来源 `b7a70bfa9e53f0a5f16619c60523c84613cb7b0b`。页面先用原 regeneration requestId、当前 factor revision 创建仅限 `RECOVERY_CODES_REGENERATE` 的两分钟 step-up，再以独立 verify requestId 提交当前密码和新 TOTP；证明不会延长有效期，也不授予额外 IAM 权限。只有首次 `APPLIED` 可以在当前 React 内存显示恰好十条非空且唯一的新码；`EQUAL_REPLAY` 和两个 by-request 查询永不返回秘密。开始、验证或重新生成结果未知时，客户端冻结原意图，验证未知只读 step-up，重新生成未知只读 regeneration，绝不自动重放密码、OTP 或写命令。相同 Account/User 正常重新登录后可以用新 Session 查询原非秘密结果；旧 step-up 证明不能跨 Session 继续使用。`NOT_FOUND` 不证明回滚，也不允许自动创建新意图。

本人正常替换已有固定来源 `e24dbdae6b4ea420365a4527a0bd89b16e0d720f`（Verification `36033828072` completed/success），但当前 UX 分支的 IAM 运行时尚未整合该路由及依赖闭包，因此 LIVE 设置页暂不暴露换绑按钮。HTTP 适配先按请求用途严格区分旧版首次绑定 wire 与新版 `REPLACEMENT`（purpose 必填），并分隔 `RECOVERY_CODES_REGENERATE`/`TOTP_REPLACE` 两种 proof，用原 requestId、stepUpId、factor revision 请求换绑；不把旧版首次绑定回包的缺失 purpose 泛化为新版替换的默认值。依赖闭包集成时应原位更新首次绑定解码器，不保留永久双契约。隔离 MOCK 先验证页内换绑和不确定结果处理：确认结果未知时禁止直接取消或再提交，只能显式模拟按原意图查询非秘密状态；模拟查询不代表真实 IAM 已确认。真实界面接入仍须确保同一 PASSWORD_TOTP Session、原绝对 120 秒窗口、`APPLIED` 一次性设置材料、成功后十码一次展示和重新登录；新 Session 只能读/取消旧待处理意图，不能接管旧证明。合法移除尚无固定客户端契约，LIVE 不提供移除。受限自助恢复只从已验证密码产生的 `LOGIN/TOTP` 或有准确恢复历史的 `LOGIN/RECOVER` 挑战进入，使用一条旧恢复码换取独立 `RECOVERY/ENROLLMENT` 挑战和一次性 provisioning；它不创建 Session、不改变密码，也不授予管理员代替本人重置因子的能力。任何真实失败不得进入 MOCK。

恢复开始一旦提交就消费旧码、终止旧因子与旧会话，关闭页面不能撤销。开始回包未知时，客户端只在内存保留原 loginName/requestId，清除 challenge secret 与 provisioning；用户必须重新以密码取得新的 LOGIN 挑战并显式查询原 requestId。`NOT_FOUND` 不证明回滚，查询不会重发秘密或自动消费另一条码；原 `STARTED` 的一次性材料已经丢失时，页面必须明确说明并由用户选择使用另一条旧码创建新意图。确认回包未知不查询或重放十条新码，只允许使用刚绑定的新因子正常登录验证结果。所有密码、旧码、新 seed、URI、OTP、challenge credential 和新恢复码均只留当前 React 内存，不进入 URL、日志或浏览器持久存储。

### 登录挑战的固定客户端接入

登录挑战消费 IAM-009 固定来源 `f5cec0e132ad18900d9a5a5629eae04fda4817f1` 及上述 S2b 增量。`POST /v1/auth/login` 只接受互斥的 `AUTHENTICATED` 或 `CHALLENGE_REQUIRED` 分支；登录入口只接受 `LOGIN/TOTP` 或有准确恢复历史的 `LOGIN/RECOVER`，绝不接受 `RECOVERY` purpose，也不会保存 bearer、创建 `Session` 或开放控制台。挑战 credential 仅保存在当前 React provider 的内存状态，不进入 URL、DOM、浏览器存储或普通 session API。

`POST /v1/auth/challenges/{id}:verify` 不携带 `Authorization` bearer，只携带 challenge credential 与验证码。它只能返回完整认证结果，或进入同一登录目的的 `PASSWORD_CHANGE`；任何混合字段、未知步骤或在错误阶段出现的合法步骤都按协议失败关闭。`POST /v1/auth/challenges/{id}:password` 与已有的会话内 `/auth/password` 保持不同：它只使用 challenge credential，成功只接受 `REAUTHENTICATE`，随后清空挑战与任何会话材料并返回普通登录，不能静默进入控制台。

受限改密的明确规则拒绝可在当前挑战中修正输入；明确失效的挑战直接清除。网络、服务端或协议错误无法证明密码未写入，页面进入独立“结果未确认”状态并清除挑战凭据，不提供原挑战再次提交；只允许回到普通登录，用新密码先核实结果。该状态既不声称改密成功，也不创建 Session 或开放控制台。

挑战到期在客户端清除秘密状态并要求重新登录；普通登录挑战取消不会复活旧挑战，恢复已经开始后页面只能放弃本地一次性材料，不能描述为服务端取消。验证码或 challenge 错误只映射为允许公开的本地提示，不把上游细节、credential 或服务端响应展示给用户。首次强制绑定另按下节受限挑战处理；通用 step-up、账号安全设置及完整发布 profile 不混入这条登录客户端。

首次强制 MFA 绑定的 LIVE 消费以固定 IAM 来源 `e24dbdae6b4ea420365a4527a0bd89b16e0d720f` 为边界，保留现有 DEV 隔离交互预览。腾讯云公开 UX 也是在未绑定子用户下一次登录时引导绑定（[身份安全管理](https://cloud.tencent.com/document/product/598/73859)）；我们只借鉴时机，不复制其扫码、代解绑或未交付的身份能力。`POST /v1/auth/login` 的 `CHALLENGE_REQUIRED` 可返回 `ENROLLMENT/PASSWORD_CHANGE` 或 `ENROLLMENT/ENROLLMENT`，绝不因此建立 Session；challenge credential 仅驻内存，不进入普通 Bearer/URL/存储。初始密码须先在受限挑战中改密，旧挑战终止，重新用新密码取得新挑战。`ENROLLMENT/ENROLLMENT` 只能按原 challenge credential 读取 `:enrollment-state`；只有后端该状态给出本人通知地址 NONE 或 VERIFIED 才进入后续，状态不可信、缺失、恢复中均失败关闭。已有 VERIFIED 地址只沿原记录使用；无可信地址先在同一挑战内通过 IAM-012 的受限验证路由证明地址，再启动首次 TOTP；绝不把普通 Session 设置的验证接口或密码字段嫁接到此流程。地址验证、TOTP 与重试共用挑战绝对五分钟期限，不能续期。`EQUAL_REPLAY` 不可显示种子，未知写入不能伪装成功或发新意图；确认结果只在可信回包返回十条一次性恢复码时展示，结束后仍须重新登录，不自动创建 Session。验收须有严格 wire/用途校验、内存状态与过期/未知结果测试及固定真实 IAM 进程浏览器闭环；未通过前 LIVE 不标记已验收。预览用固定虚构地址、密钥、验证码和恢复码，不调用 IAM、不收集真实密码或地址，也不创建登录会话。

### 账号级 MFA 要求的隔离体验

账号级 MFA 要求遵循 IAM-009 S2/S3 的固定设计来源 `d570673ba87c113f7474fdab79b5e22a83c2b323`。当前 UX 分支固定运行时来源 `018fbd7505ae16d59dcfe857df7fbbe870bf1a13` 只提供 `GET /v1/account/security-settings` 和精确当前 Account 实例的 `iam.security-settings.read`；新版写入、专用 step-up 与历史读取虽已由固定来源 `e24dbdae6b4ea420365a4527a0bd89b16e0d720f` 定义，仍未整合到本分支运行时。非体验设置页因此只读取当前账号规则，严格核对版本、归属、显式布尔值和更新时间，不带 Account selector，不由旧系统策略或 Root 名称猜测读取权限。401 仅过期发起请求的会话；403 是局部无权，不清除登录态；404 和其他失败不回退 MOCK。固定标题与卡片保持，只有规则数据区加载或报错；`requiredForUsers=false` 不代表个人未绑定因子或当前会话未完成 MFA。

独立 DEV 体验把规则作为不同于本人认证器、恢复代码与安全通知地址的 Account 设置呈现：模拟编辑后先审阅准确的 Account 目标、适用身份和会话影响，再完成仅绑定本次规则变更的密码加 TOTP step-up，最后只写入隔离仓库。正常审阅不展示失败模式选择；MOCK 异常路径收在次级展开项中，仍可验收拒绝、冲突和响应丢失。step-up 只证明认证强度，不授予 IAM 权限；真实保存仍须由后端重新鉴权，任何真实读取或写入失败都不得回退 MOCK。

新版写入客户端先冻结 `expectedResourceVersion` 与准确 `mfa.requiredForUsers`，以 `SECURITY_SETTINGS_UPDATE` 和当前因子版本创建只限本操作的证明；验证与 `PUT /v1/account/security-settings` 分开，写入仍携带原 requestId、stepUpId、冻结版本及目标值，不发送 Account selector。`APPLIED` 与 `EQUAL_REPLAY` 都须严格核对同 Account、同原请求、目标值、版本恰好加一与 `callerSessionEnded=true`；后者只说明原调用 Session 已终止，不应注销后来查询的新 Session。结果未知后不能以新 requestId 重写，正常重新登录后只能在当前读取权限下查询 `/v1/account/security-settings/changes/{requestId}` 的同一原意图；`NOT_FOUND` 不证明未提交。当前只准备未挂载的 HTTP 适配和隔离 MOCK 交互，LIVE 写入口、真实 IAM 浏览器与发布验收等待依赖闭包集成。

规则只覆盖普通 IAM User。Account Root 与仍由平台管理关系保护的身份不适用；收紧规则会使不再满足要求的普通 User 会话重新认证，放宽规则不会恢复已经失效的会话，也不会删除个人已经绑定的认证器或恢复代码。审阅页必须固定并复述上述范围，不能用一个通用确认替代目标和副作用。

控制台不公开任意密码长度或泛化“敏感操作”选择器，也不把 step-up 票据抽象成通用提权令牌。账号会话只在下节封闭的空闲策略预览中出现，不能泛化为角色、应用或后台会话的共同“会话时长”。当前预览只验证信息架构、审阅与焦点体验，不声称 Account 安全规则已由真实 IAM 保存或执行。

DEV `AccessSettings` 只拥有账号级 MFA 要求与交互式控制台 Session 空闲策略。用户 SSO 不再借用账号安全设置或预览保存命令，而由下文独立、只读的概念页说明其对象和前置条件。先前没有 IAM 契约所有者的任意密码长度、密码到期、密码复用、通用账号会话时长及泛化“敏感操作保护”字段已经从领域模型、预览仓库和安全报告中替换删除，而不是继续隐藏在页面背后。安全总览只呈现能够说明证据来源的五项检查：访问密钥、直接授权、登录保护、待重置密码和 MFA 证据；隔离空闲策略预览也不得伪装为真实后端已经执行的安全检查。

### Passkey / WebAuthn 的概念级体验

DEV `AccessSettings` 在现有安全通知、TOTP 与恢复码之后提供独立标记的 Passkey 概念预览，只验证公有云控制台中的信息架构与浏览器仪式前后责任边界。摘要明确私钥始终留在认证器、方法只属于当前 Account 的现有 USER 且不替代 Role 或应用凭据；当前平台固定显示“未配置 · 尚未启用”，不伪造设备目录、最近使用或可信状态。拟定状态口径分别解释未配置、已有配置事实但生产前置未满足，以及只能由 IAM 权威判定的可用／受限状态；浏览器能力、本地设备或页面逻辑都不能升级状态。

已推送的 [`ed4e3e69c`](https://github.com/xiak/matrix/commit/ed4e3e69c) 将 IAM owner 对齐的 FEAT-IAM-012 IAM-EXT-05 边界原位收进既有组件：RP ID 与 origin 必须来自安装可信配置，页面、请求或租户管理员均不能选择；注册和删除分别要求绑定准确操作、凭据、Account、User、Session 与认证器修订的 step-up；账号已配置通行密钥不会升级既有 Session；sign counter、同步型凭据等异常只能由 IAM 失败关闭或进入明确风险状态；丢失设备只能走既有受控恢复，不能绕过 MFA、恢复已撤销权限或产生万能恢复角色。当前正式域名、可信 origin 与真实设备前置未满足，因此组件只使用本地展示状态，不调用 `navigator.credentials.create` 或其他 WebAuthn API，不触发系统提示，不创建、上传或保存凭据，也没有注册、删除、重置、恢复、保存或启用动作。它不扩张 `AccessWorkspace` 领域模型、仓储命令、HTTP 适配、SQL 或登录路由；真实契约固定后必须原位替换，不能保留平行预览模型。

组件初次挂载不再把焦点从页面主标题抢到下方 Passkey 标题；只有用户主动进入、返回或完成预览时才移动到准确阶段标题。定向行为用例锁定三类状态、零敏感动作、可信依赖方、Session、风险与恢复边界。完整前端 62 文件／1046 条用例、三条静态归一化、类型、lint、架构、228 组主题对比、45 路由导出、249 文件嵌入等价及全仓 Go test/vet 通过；桌面与 `390 × 844` DEV 实看信息层次清楚，窄屏 viewport/document/body 均为 390px，预览无输入控件、Dialog 或可提交成功态。该证据不声明 FEAT-IAM-012 已实现、真实设备可用或后端／发布门禁已完成。

### 交互式会话空闲策略的隔离体验

DEV 体验把空闲策略作为独立于 MFA、角色承担时长与应用后台任务的 Account 安全设置。摘要同时显示最长空闲时间、适用会话、哪些明确前台操作可以触发续期、哪些后台请求不算活动，以及绝对到期仍是硬上限。编辑只给出 5–60 分钟的受控选项；审阅固定显示旧值、新值、规则更新会因安全设置版本变化使既有登录会话和挑战失效、新会话冻结新值，以及 Account Root 和持有未撤销 installation 级平台附件的受保护 User 不会因账号规则放宽而超过 30 分钟。规则更新不停止工作负载，也不赋予平台权限。这个信息层级借鉴 Azure Portal 的租户级最长空闲策略与 AWS IAM Identity Center 的交互式会话设置 UX，但不复制其身份模型、生效语义或数值范围（[Azure Portal preferences](https://learn.microsoft.com/azure/azure-portal/set-preferences)、[AWS user interactive sessions](https://docs.aws.amazon.com/singlesignon/latest/userguide/user-interactive-sessions.html)）。

当前实现仅在隔离预览组件的本地状态中审阅和应用，不扩张 LIVE `AccountSecuritySettings` wire、HTTP 解析器、`SessionProvider` 或仓储命令；不注册鼠标/键盘等全局活动监听，不启动前端倒计时，不在后台轮询、预取或普通 Bearer 请求中触发 touch，也不把真实读取失败回退成预览值。待 IAM 工程师给出已推送固定来源后，再原位替换为真实账号设置、显式前台 touch 与严格 Session 事实；不能凭当前预览推导 endpoint、绝对时长或可写能力。

### 用户 SSO 与角色 SSO 的隔离体验

角色 SSO 的 IdP/Role 信任与用户 SSO 的 Account 登录配置是两条不同旅程。腾讯云公开说明角色 SSO 使用身份提供商与 Role，用户 SSO 则把企业身份映射到已有子用户；启用后会改变子用户的控制台登录路径。其 [角色 IdP](https://cloud.tencent.com/document/product/598/30290)、[用户 SAML](https://cloud.tencent.com/document/product/598/61674) 和 [用户 OIDC](https://cloud.tencent.com/document/product/598/93431) 配置分属不同页面。我们不复用角色提供商 ID 作为用户 SSO 前置条件，也不因为用户 SSO 配置推断 Role 信任或资源授权。

角色 SSO 当前只保留身份提供商配置与 `RoleSsoMappingPreview` 的隔离浏览器内存样例。映射样例描述 provider、外部主体样例与目标 Role 的设计关系；外部主体只用于解释未来映射输入，不是精确 claim 规则、候选角色 DSL、Account、User、外部主体目录记录或已发布后端资源。它不能同步目录、接受或验证真实断言、证明登录、创建 RoleSession 或参与有效权限判定。没有固定 IAM 来源前，页面不建立 HTTP、持久对象或成功承担路径；后端给出固定、已推送且明确可消费的 IdP/Role trust 契约后，再原位替换该预览，而不是保留兼容别名或并行模型。

隔离样例按 IAM 工程师为 IAM-EXT-03 给出的目标语义显示六段安全边界：验证企业 IdP、把外部断言视为不可信输入并完成签名/时效/重放校验、由已验证映射形成可选角色集合、独立检查目标 Role 的 `TrustPolicy`、独立检查调用方的承担角色权限，最后才由 STS 签发有界 `RoleSession` 并保留原 Provider 和 opaque 外部身份供审计。Role Trust 与承担权限是两道独立门禁，任一道不成立都不能签发会话。该顺序只用于提前验证公有云 UX 和操作者心智模型；前端不为这些阶段新增状态机、命令、仓储、请求号或成功状态，也不从现有 provider、映射和 Role 样例推断真实断言已经通过校验。

用户 SSO 页继续保持只读，但不再用“未配置”掩盖已有的稳定投影。隔离 `AccessWorkspace` 只展示同一 Account 中 `IdentityProvider` 的协议、Issuer 与状态；仅 OIDC 样例附带 Redirect URI，SAML 的 metadata、证书与 ACS 以及 OIDC 的 discovery/JWKS、client 与回调登记均保持未冻结。页面另展示 opaque `ExternalIdentity` 到既有 `USER` 的映射；Account 是只读归属事实，不是可切换目标。跨 Account、未知 Provider、空或控制字符主体、未知 USER 均失败关闭且不进入可用投影。Provider 停用只表示依赖它的新 `Session` 签发必须失败，不宣称既有 Session 已撤销，也不改变该 USER 的直接策略或用户组授权。页面不会把外部目录组转换为 Matrix Group/Policy，也不会把用户 SSO 与 Role 的 `TrustPolicy`、角色选择或 `RoleSession` 合并。

页面只用协议作为分类，不把 SAML XML、证书、公钥、OIDC discovery/JWKS、client secret、私钥、回调登记或 claim DSL 预先塑造成共同后端字段。浏览器内的 `principalType: "provider"` 及只读 JSON 中的 `MOCK_IDENTITY_PROVIDER` 只是显式预览判别值，绝不写入当前只接受 `USER`／`SERVICE_ACCOUNT` 的后端 PrincipalType。另以安装登录入口、协议验证生命周期、外部主体唯一映射、应急恢复、审计与 Session 五项就绪条件约束后续实现。用户 SSO 页没有输入、按钮、Dialog、成功态或浏览器跳转，不提供 IdP 增删改启停、秘密上传、测试连接、USER 绑定/解绑或登录/登出。上述能力必须等待 IAM owner 固定真实领域、wire、安全与运行时契约后原位接入，不能从概念页反推后端字段或可用状态。

安全总览把“建议结论”和“证据覆盖”作为两个独立维度。建议结论是需复核、已配置、状态未知或不适用；证据覆盖是已观测、覆盖不完整、未观测或不适用。未观测不等于没有活动，分页目录不完整时也不能把已加载用户的结论外推到整个 Account。页面和导出的 MOCK 报告都必须保留该差异，不能制造风险分、在线状态、来源位置、AccessKey 最近使用时间或其他未被权威数据支持的事实。

### 只读权限能力目录

策略工作区以独立“权限能力目录”页签消费 `GET /api/iam/v1/authorization-profiles`。请求不携带 Account、修订、分页、历史或正文 selector；客户端严格验证完整列表、产品顺序、Action 命名空间、scope、资源 shape、可信条件组合及内容摘要格式，并再次核对响应 Account。按固定后端 `29668fa330b2233b43ebd48ed37738623377f9de` 的声明完整保留 `subjectTypes` 与 `userAuthenticationMethods`，显式空/null、重复、未知类型或不支持 USER 却声明用户凭证均拒绝。字段缺省保持原声明字节的历史上限：普通 scope 仅 USER、INSTALLATION_PROBE 仅 SERVICE_ACCOUNT，支持 USER 但未声明凭证时仅 LOGIN_SESSION；不向声明中补写默认值。目录详情分别说明身份和凭证适用性及历史默认，不能从 USER 推导 ACCESS_KEY 或 ROLE 能力。目录描述平台登记的产品能力，不是当前身份权限，也不是租户产品发布入口；浏览器不重算后端权威摘要，也不从目录推导最终 Allow。

目录不加入 IAM 初始场景的组合读取。只有首次打开页签才局部加载，固定的目录说明、搜索框和状态区同步呈现；需要等待时仅表格数据区域沿公共 `TableSkeleton` 延迟反馈。局部失败与重试保留同一个搜索控件和输入内容；详情只从当前已验证的目录快照取值，不保留可能过期的产品对象。401 只过期发起请求的当前会话；403、路由不匹配、5xx、网络、协议或 Account 不一致只关闭该目录并提供本地重试，不清空策略页面、不回退 MOCK、不伪装为空成功。

产品详情在同一内容区展示完整当前声明，并保留目录搜索、公共表格、分页、移动堆叠和进入/返回焦点。`INSTALLATION` 与 `INSTALLATION_PROBE` 只作为平台范围元数据展示，不能在租户 CUSTOMER 作者流程中选择。DEV 体验仓库提供同结构的隔离示例，但显式标记 MOCK、示例摘要不可信且不授予真实权限。隔离示例还把责任边界原位分开：租户管理员只消费已发布目录来编写和分配策略；产品研发声明 Action、资源和条件能力，IAM 平台校验并受信发布。内部接入审阅只从后者进入，不再放在租户产品详情标题旁伪装成客户操作。

自定义策略的 LIVE 新版本作者依照 IAM 工程师固定来源 `aefe4f786242d7d6816f253b6389d5c94c314a75` 的 CAT-06/IAM-005 边界，在原 JSON 路径旁提供目录驱动的可视化编辑：只在主动打开可视化页签时读取当前完整目录，不因打开版本详情或 JSON 编辑而请求目录。每条声明可选 1–128 个同产品、同资源类型且资源形状兼容的准确 `TENANT` Action；产品与资源类型来自声明本身，不靠 Action 名称猜测。操作共用该声明的资源和条件；资源选择器只表达 `EXACT`、全部所选操作均支持的字面 `PREFIX_IN_AUTHORITY` 和 `ANY_IN_AUTHORITY`，条件只表达全部所选操作共同声明的 IAM 身份/时间键及 IAM-005 封闭操作符。集合目标、集合用途与成功结果资源用于说明能力，不被误写成资源选择器。Action 分页、已选筛选、声明选择与资源/条件编辑只挂载当前声明和当前操作页，避免目录增大时整页渲染所有表单。

JSON 是无损来源：含 Action 家族、跨产品/资源类型或资源形状不兼容的多 Action 声明、未知字段或当前表单无法完整表达的资源/条件时不切换为部分可视化，更不会丢弃原文。目录无权、路由缺失、会话失效、网络或协议失败时可视化区局部失败，JSON 仍可用，不回退 MOCK。可视化草稿只在审阅前对可见字段做轻量检查；目录不是权限、资源清单、编译预演或 Allow 结果。发布仍提交 `languageVersion: "1"` 的 `PolicyDocument` 到已有 IAM-005 审阅与版本命令，保留原 requestId/资源版本/结果未知恢复边界；不提交目录、摘要、编译快照或虚构的 language version 2。完整合法性由 IAM 发布时校验。

### 当前身份的权限上限投影

严格消费必需的 `CurrentIdentity.permissionBoundary`，匹配当前 Account、User 和 User resourceVersion。缺字段、错误归属/修订、非法引用或摘要使读取失败；只有明确 `policy: null` 表示无边界。RootIdentity 只允许明确无边界。

概览独立展示 Policy ID、默认版本引用和内容摘要，不加入正向 policySources。无边界不等于有权限，有边界不等于获得授权。无 Policy 正文读取权仍可以展示自身引用，但不能因此读取正文或其他 Account。重新读取失败不把旧引用或 null 作为当前事实。

### User 边界管理

沿 User 内容区详情使用现有 GET/PUT/DELETE permission-boundary 契约，不增加顶层边界目录、通用注册功能或客户端求值器。UserAccess 的九项基础能力包含精确 USER 的 set/remove；普通管理员即使有动作 Allow 也不能据此绕过后端原 Account Root 关系约束。

进入详情独立读取 User 和边界，归属及 User 修订必须一致。失败不显示“无边界”。策略选择只使用已授权可见、ACTIVE/TENANT、系统或同 Account 的目录记录；目录无权不可选新策略。目标停用状态与边界管理可用性不能互相推导。

设置、替换、移除均先审阅后显式确认。冻结 Policy ID/修订、目标 User 修订、默认版本引用及 requestId；移除说明其他正向授权可能重新生效。它不修改附件、启用状态、凭据或用户组。

| 结果 | 客户端行为 |
| --- | --- |
| 等待写入 | 立即反馈，阻止重复提交和离开待提交场景 |
| 网络/503/非法成功回包 | 不确定状态；锁定意图，只能显式重试完全相同的请求，不生成新 requestId |
| 409 | 保留选择，重新读取最新修订，再审阅并表达新的提交意图；不自动写入 |
| 400/403 | 明确失败，不猜跨账号对象，不提交替代选择 |
| 401 | 只过期发起请求的当前 bearer；清除私人管理状态，迟到的旧请求不能撤销新登录 |
| 已确认写入、后续读取失败 | 保留确认结果，锁定编辑；只重试读取，不重发已成功写入 |
| 完成并重新读取 | 仅更新当前 User 详情、边界和 capability，不重新加载全局 IAM 目录或 Header |

长 Policy/版本/摘要使用原公共排版和主题系统，窄屏完整换行。加载、空状态、操作及审阅继续复用现有公共组件。页面路由与客户端详情 query 的划分、静态入口及滚动归 [FEAT-007](../docs/features/FEAT-007-control-plane-console.md) 所有。

### 策略版本的隔离体验

策略详情把不可变版本、当前默认版本与策略使用关系分开。版本号直接打开当前内容区中的只读正文；自定义策略的非默认版本仅通过一个行内更多菜单进入“设为默认版本”或“删除版本”，不在表格中并排堆叠多个操作。切换默认版本必须先在内容区审阅策略差异、完整 JSON 与受影响的 User、Group、Role 和权限边界；删除必须展示准确版本正文。默认版本不能删除，查看与取消不会改变任何关联。

进入、返回、取消、失败重试和完成均保持当前策略详情、页签、滚动与键盘焦点，不打开 Dialog。当前版本模型和写入仍属于隔离 DEV 体验仓库，不能据此声明真实 PolicyVersion 正文、默认版本变更或服务端编译快照已接入；真实 API 固定后另片替换仓库，失败不得回退 MOCK。

### LIVE 策略版本变更边界

活跃租户 CUSTOMER 策略才在真实版本目录显示切换默认与退休入口；只有非默认版本可操作。入口只按对象适用性出现，不借 Root 标签、目录可见性或策略名称推断操作者有权；IAM 在每次写请求上独立鉴权。审阅使用同一次准确版本目录的 Policy resourceVersion、当前默认版本、目标不可变声明与内容摘要；真实后端尚无完整反向关联目录，页面只能说明 User、Group、Role 等引用可能受影响，不能虚构受影响主体数量。

切默认与退休分别使用 IAM-005 精确写路由，不把发布版本、设默认与授权合为一个动作。退休仅移除非默认版本的可管理槽位，历史证据仍保留。提交前先登记同一 Account/会话的原 requestId、resourceVersion 和完整输入；网络、5xx 或协议回包不可信时，原意图维持 UNKNOWN，禁止第二项版本变更。只能用原输入等价重试；重试 409 仍不能证明原写入成功或失败。准确重读当前 Policy 和版本目录仅呈现“现在是什么”，不证明原请求的因果结果；操作者确认已核对且接受未知结果后，才明确结束旧意图，新变更必须从最新目录重新审阅。401 仅过期原认证代次，403 不清除登录态或回退 MOCK。

新版本发布复用策略创建的 JSON/可视化作者及审阅摘要。可视化审阅逐声明核对效果、精确 Action、资源选择器与条件；多声明仅挂载当前摘要，当前默认版本和待发布版本的完整 JSON 对照按需展开。自由 JSON 编辑继续直接展示完整对照，不能以可能遗漏未知字段的摘要代替。发布成功说明只适用于该次已确认结果；进入后续默认切换或退休审阅时结束旧提示，确认变更也清除它。重新读取后仅在默认指针和已发布版本仍与说明一致时呈现，不显示过期的“默认版本仍未变”。摘要、目录和对照均不构成 IAM 语义校验，也不改变发布后默认版本仍保持不变的边界。

### LIVE 自定义策略新建边界

固定 IAM-005 的 `POST /v1/policies` 只接受 `displayName`、`document` 与 `requestId`，由当前认证身份确定 Account；前端不发送 Account selector、策略 ID、管理类型或关联主体。创建只产生当前租户的 CUSTOMER Policy 与首个不可变默认版本，不附加用户、组或角色，也不自动改变已有身份权限。名称在本租户有效自定义策略中精确唯一；客户端检查 128 字节名称与 64 KiB 完整请求预算，128 个活跃策略上限及完整语义仍由 IAM 在事务内最终判断。目录可见性或当前按钮显示不能推导创建权限；403 保持在本流程，不回退 MOCK。

创建页与版本作者复用同一 JSON/可视化编辑边界。JSON 允许完整声明，目录不可用时仍可用；可视化只在主动选择后读取当前权限能力目录，用户须明确选取精确 TENANT Action。新实例声明默认要求填写 `EXACT` 资源 ID，集合型 Action 的精确目标才默认字面量 `collection`；扩大到 `ANY_IN_AUTHORITY` 必须由用户主动选择。切换编辑模式不得丢弃无法无损呈现的 JSON。可视化审阅先逐声明核对效果、Action、资源与条件，完整 JSON 按需展开；多声明只挂载当前摘要。摘要不代替完整文档或 IAM 校验，JSON 自由编辑模式继续直接展示原文，不能概括掉无法无损呈现的字段。审阅显示名称与“创建不等于授权”，成功显示服务端稳定 ID，再由用户进入详情；显式 MOCK 四方法仍独立保留。

提交前在当前 Account/会话冻结名称、完整文档与原 requestId。网络、5xx 或无效成功体使创建结果 UNKNOWN，跨内容页导航仍保持原意图，只能用完全相同输入重试；Profile 推进或并发导致的重试 409 不证明原请求是否成功。同名目录项不是请求因果证明，不能自动清锁；操作者核对后明确承认未知并结束旧意图，才允许另起创建请求。首次明确 400/401/403/404/409/413/415/422 按分类反馈；401 只过期发起请求的会话。当前没有跨重新登录的 by-request 查询，因此此片仍不构成可发布的未知结果闭环。

### Role、trust 与会话的契约对齐体验

角色体验以 IAM-006 的固定来源
`62a18a48168e87a4158b95eba41427b445ed10d1`、公开数量边界修正
`0567c8b2699521b137db0f8b69f17630c59f04fb` 和来源身份不可复活修正
`1ebab37aef4bce12b963f52d3919748a9d50d4c6` 为 LIVE 接入依据。管理侧 Role list/read 已由严格客户端接入该固定来源：Account 只用于核对当前认证上下文，不能作为调用者可选参数；响应中的 Role、trust version、policy attachment、能力快照、时间、排序和摘要必须完整核对，协议不符或真实请求失败都不能回退 MOCK。能力快照只描述这次响应允许呈现的动作，不能缓存为后续变更或 AssumeRole 的授权结论。

LIVE 管理片提供角色目录、详情读取和角色创建。固定标题、说明、搜索和筛选立即呈现，仅数据区局部加载；目录使用不伪造总数的 opaque cursor，详情与创建向导都在内容区展开，不打开 Dialog。创建只提交当前认证 Account 下的角色元数据与首个不可变 USER trust 版本，不附加策略、不设置权限边界、也不签发密码、长期密钥或临时凭据；客户端不发送 Account selector。真实首版信任仅接受已读取的同 Account 精确 User，信任准入不替代调用 User 对目标 Role 的承担授权，也不授予 Role 对业务资源的访问权。会话时长限制为 1–720 分钟，对应 wire contract 的 60–43200 秒。创建结果未知时，页面冻结原 payload 和 requestId，只允许等价重试；离开页面会明确提示无法再以新意图证明原请求是否提交。服务身份、身份提供商、跨账号、角色链和通配信任仍属后继能力；体验仓库已有的服务/联合示例继续标成合成 MOCK，不能映射成真实能力或可发行的临时凭据。

LIVE 角色详情把当前策略附件、当前权限边界和当前 USER 信任主体作为可追踪关系：使用响应中的精确 Policy/User ID 进入既有详情页，目标页自行执行读取和 403/404 失败关闭，不在角色页逐行请求显示名称。当前关系可导航不表示最终 Allow、承担资格或目标可读；Policy attachment 只是角色策略来源，权限边界只收窄上限，trust 也只描述承担准入。不可变历史 trust 版本继续显示原始文档证据，不把其中旧 USER 解释为当前关系或导航入口，也不把后继服务主体伪装成普通 User。

角色信任关系是详情页中的完整配置工作流。LIVE R1 在当前 trust 页签内编辑、严格校验、审阅前后完整 JSON 文档，再显式替换；只接受同账号明确 USER ID、最多八条声明、每条最多 32 个主体，`DENY` 优先，空 statements 表示无人可信。通配符、Group、Role、Service、IdP、条件和跨账号主体保持关闭。返回、取消、失败重试和完成都不打开大型 Dialog，并恢复到稳定触发器。同账号 USER 的 MOCK 预览沿用同一 `TrustPolicyDocument` 信息形状但继续由隔离仓库保存；服务与身份提供商只展示明确标记的合成主体，不伪装为 LIVE 信任文档。信任只是承担准入，不替代调用 User 针对该 Role 的 `iam.role.assume` 授权，也不授予角色资源权限。

管理员的角色会话目录与成员自服务承担必须分开。管理目录只展示非秘密会话记录、来源 User、到期/撤销观察和单条撤销能力；`UNREVOKED` 只表示在该观察时刻既未撤销也未到期，不得翻译为“当前仍可用”。管理员角色详情不提供创建或模拟承担入口，隔离 MOCK 也遵循同一信息架构；可承担角色发现、承担审阅和体验身份只存在于独立成员自服务入口。撤销确认留在内容区，目录行只保留单个更多菜单；不确定撤销结果保留原 requestId，只允许等价重试或读取该会话的权威状态，读到 `REVOKED` 也不能据此声称是此前未知命令造成。

LIVE 成员入口只用当前 USER bearer 发现其本人的可承担 Role；Account、来源 User、trust 结果和承担授权均由后端上下文决定，页面不提供身份选择器。固定身份/边界先呈现，只有目录数据区延迟骨架；选择后在内容区审阅准确 Role、资源版本和有界时长。首次 `APPLIED` 的 Role credential 只留 React 内存，必须通过 CurrentRoleIdentity 精确核对 Account、Role、来源 User 和会话后才替换业务 credential；`EQUAL_REPLAY` 与按原请求查询都不含秘密，不能恢复或猜测 credential，只能先撤销已定位会话再创建新意图。Role 模式不复用来源 USER 的 IAM 管理目录或产品 credential；产品请求统一消费核验后的有效身份。

退出 Role 不签发或复活 USER credential。客户端先停止 Role credential 的业务使用，以原 logout requestId 等价重试；只有确认 RoleSession 已撤销后，才用原 USER bearer 调用 `/auth/me` 重新核对同一 Account/User 并恢复 USER 模式。网络、5xx、401 或协议失败均是退出结果未知，不能显示已退出；显式兜底也必须先重新核对来源 USER，再按原承担 requestId 撤销对应会话。浏览器刷新或进程丢失不会持久化 USER/Role credential，要求重新登录。

成员自服务 MOCK 会话从实际点击承担的时刻计算签发与所选时长，不使用陈旧示例时间冒充当前会话。到期后即使浏览器标签页曾在后台，也不能继续显示“可用角色身份”或退出有效会话的动作；返回角色发现是新的体验入口，不表示真实 RoleSession 的服务端状态已被本地时钟证明。

### 访问密钥生命周期的契约对齐体验

访问密钥体验以 IAM-007 当前固定来源 `91649497a0c53be1174d8835326a2df51fe74a55` 为 LIVE HTTP 接入依据，其中来源网络与授权观测的生产契约由 `472596b1edf5fc0fa3f908294bae0624d581dc4f` 引入；精确源码的 Verification `37106511260` 已完成且 15 个任务全部成功。它只管理 same-account 非 Root User 的长期编程凭据，不与登录会话、RoleSession、服务身份或 Account Root 混用。入口先选择 User，再读取该 User 的密钥；控制台不能为了方便伪造一个后端并不存在的 Account 全局密钥目录。

每个 User 最多拥有两个未删除密钥，`ENABLED` 与 `DISABLED` 都计入上限。推荐轮换顺序固定为“创建第二把 → 外部验证工作负载 → 停用旧密钥 → 删除旧密钥”；删除不可恢复且只允许删除已停用密钥。密码变更、退出登录或会话撤销都不能显示成会自动停用或删除访问密钥。

创建和重新启用只对 `ACTIVE` 且没有强制改密状态的 User 开放；这些状态仍不阻止具有精确能力的操作者读取、停用或删除既有密钥。LIVE 客户端必须消费 AccessKey 专属 `ActionCapability` 与平台保护事实，不能从 User 列表/读取能力、显示名称或 `enabled` 状态推断密钥管理权限。

Secret 只在创建结果明确为 `APPLIED` 时展示一次，并在确认离开后从 DOM 与页面状态移除。网络或 5xx 导致结果未知时必须把原 owner、规范化后的 `networkRestrictions` 与 requestId 作为共享未决意图保留；`UNKNOWN` 不包含也不要求客户端尚不知道的 keyId。切换 User、返回目录、组件重新挂载或生成新 requestId 均不能绕过。原 owner/requestId 的完成映射不可覆盖；相同创建请求的重放不能创建第二把密钥或重发 Secret。by-request 查询的 `NOT_FOUND` 与暂不可用都继续保持 `UNKNOWN`，只有可核对的已提交结果才揭示非秘密 keyId。查询若确认已创建但 Secret 已丢失，先停用并删除该密钥，之后才允许创建新意图。初次创建元数据重放只证明原结果，不证明密钥当前可用。页面只显示固定 `usage.observedAt` 和可选 `lastAuthorization`，不把它们改称 last-used、活跃工作负载或“可安全删除”结论。

### 访问密钥网络治理与授权观测

公有云常见的长期凭据治理需要把账号统一底线、单把密钥的进一步收紧和请求时授权重新求值分开呈现。固定来源 `91649497a0c53be1174d8835326a2df51fe74a55` 已把这些事实纳入当前 wire：每个密钥必须带 `networkRestrictions` 与 `usage`，账号安全设置必须带完整 password、session 与 access-key-network 三段，密钥网络更新使用独立 `iam.access-key.set-network-restrictions` 能力和专用 PUT 路由。LIVE 严格消费该契约；显式 DEV 仓库保留同一信息架构用于随时验收，不再维护一套候选对象或兼容形状。

账号层和密钥层分别保存完整 `allowedSourceCidrs` 列表：空列表表示该层不限制；两层按 AND 合并，同一层多个 CIDR 按 OR 匹配。`0.0.0.0/0` 只覆盖 IPv4，`::/0` 只覆盖 IPv6，两者都不等于空列表。编辑是全量替换而不是追加；最多接受 16 个严格规范、去重、排序后的 IPv4/IPv6 网络，拒绝带主机位的网络、zone、IPv4-mapped IPv6、非规范前导零和重复项。账号层属于完整账号安全设置，复用其资源版本、本人因子、专用 step-up 和变更后重新登录边界；密钥页只读取这层事实。密钥层属于准确 AccessKey，使用该密钥资源版本与独立网络限制动作，不能借用启停命令；无变化审阅不允许提交。

创建流程在一个意图中冻结准确 User、User 资源版本、规范化后的密钥层 `networkRestrictions` 与 requestId，并把密钥和其来源网络边界作为同一创建结果提交；UI 不先创建无限制密钥再补写限制。同一 requestId 只能精确重放原意图，版本或 CIDR 改变时失败关闭。响应丢失继续显示被冻结的版本和两层来源范围，只能恢复非秘密 keyId，不能补发 Secret。

密钥详情把两层同时呈现，使管理员能解释最终来源边界而不把单层规则误读成全部保护。最近授权观测仅显示服务端观测水位 `observedAt` 和可选历史 `lastAuthorization` 的求值时间、Allow/Reject、Action、产品与可信来源 IP；最近 Allow 不是当前 permit，最近 Reject 不证明密钥已停用，缺少记录是未知而不是从未使用。每个业务请求仍须重新校验密钥、User、当前策略、权限边界、目标资源、条件和两层网络限制；浏览器不探测或提交自身 IP，也不据此给出健康分、在线状态或安全删除建议。

### 剩余接入边界

来源 IP 与请求时间继续只存在于隔离 MOCK 策略作者和本地策略覆盖预览。页面必须明确这些值由操作者构造，不探测当前浏览器地址、不信任转发请求头，也不模拟网关、代理或产品 PEP；覆盖预览只登记字段，不把值送入策略求值，也不从缺失上下文推导任何结论。公有云常见的 IP、网络端点及代理链条件具有不同可用性，Matrix 只有在 IAM Profile、受信请求上下文来源、操作符和产品执行边界固定后，才把相应条件开放到 LIVE 可视化作者。JSON 作者仍可无损保留服务端未来支持但当前表单无法表达的条件。

真实策略新建、版本读取、发布、切默认与退休已有前端客户端，JSON 与当前目录驱动的可视化作者也已有行为测试，但仍需与固定 IAM 进程完成浏览器联调；当前目录元数据和边界引用不能替代这些权威结果。Action 家族、跨资源类型多 Action 可视化、更多云产品条件与资源挑选尚未纳入 LIVE 表单；现有 DEV 创建策略四路径仍是隔离 MOCK 体验，不构成 IAM 当前发布能力。只读权限能力目录客户端同样仍需真实进程浏览器验收；产品声明管理不是租户策略功能。

Role 管理 list/read/create/update/status/delete、R1 trust 完整替换、单条 policy attachment 关联/撤销与权限边界设置均已有固定 LIVE 客户端；成员可承担角色发现、AssumeRole、当前 Role 身份和 Role logout 已由独立真实 IAM/PostgreSQL 浏览器 fixture 完成基础闭环。管理员 RoleSession list/read/revoke 与成员签发结果 by-request 恢复/撤销也已有固定客户端，但 Role 写入的真实浏览器故障注入、策略附件完成查询终态、Role 凭据业务产品请求以及承担/退出不确定结果仍需真实进程验收。前端不得从当前目录存在／不存在推断未知写入结果；没有完成查询的 Role 命令只能在原页面保留冻结 requestId 并等价重试。恢复码再生成的固定 LIVE 客户端已经完成，但仍需固定 IAM 进程验证 step-up、一次性秘密交付和重新登录查询闭环；账号安全设置已开放完整 password、session 与 access-key-network 读取及账号来源网络写入体验，但其 step-up、Session 终止与不确定结果仍待真实浏览器闭环。SSO 与其余登录安全专项按各自固定后端契约推进。访问密钥 LIVE 客户端已固定到 IAM-007 的每用户管理、网络限制和授权观测契约；当前真实浏览器只证明了无权时的 `403` 失败关闭，创建、一次性 Secret、轮换和网络限制仍未验收。产品 Profile 尚不接受 AccessKey，不能据此宣称云产品 API 已可使用长期密钥。本片不宣称全部错误页面或完整访问管理已验收，也不改变保留 MOCK 验收入口的安排。
